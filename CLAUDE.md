# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is LLui

LLui is a compile-time-optimized web framework built on The Elm Architecture (TEA), designed for LLM-first authoring. It runs on a **signal** runtime (`@llui/dom` — a single import surface; there is no legacy runtime and no `/signals` subpath). There is no virtual DOM — `view()` runs once at mount, building real DOM nodes with reactive bindings. State changes drive a **chunked-mask reconciler**: each binding carries a sparse mask of the dependency-path chunks it reads; on update the runtime computes the dirty chunk-set from old→new state (reference-equality per path), gates out bindings whose mask doesn't intersect it, then commits only values that actually changed (output-equality). Structural primitives (`branch`, `each`, `show`, plus `unsafeHtml`/`lazy`/`virtualEach`/`foreign`/`portal`/`provide`) are **lazy `Mountable`s** — recipes that build their live nodes and register their reconcile spec / child scope at the point they are _placed_ (materialized by `populate` for element children and by `runBuild` for a build's returned array, both under a live build context), not at construction. So a `Mountable` captured in a variable and reused inside a toggling `show`/`branch` arm rebuilds fresh on every remount (spec lands in the placing scope); placing one twice yields two independent live instances. They reconcile arms/keyed rows and own child scopes.

The Vite plugin runs a **single signal transform** (`@llui/compiler`) via the TypeScript Compiler API: it lowers signal expressions in a component's DIRECT view to runtime helpers (`signalText`/`el`/`react`/`signalEach`/…) as an optimization, emits introspection metadata, and runs the signal lint rules as non-bypassable build errors. Anything it can't lower (view-helper functions, block-body views) runs via the real runtime authoring helpers (which consume signal handles), so both forms coexist.

## Commands

```bash
pnpm turbo build          # Build all packages (tsc)
pnpm turbo check          # Type-check all packages (tsc --noEmit)
pnpm turbo lint           # ESLint all packages
pnpm turbo test           # Run tests (vitest) across all packages
pnpm format               # Prettier format everything
pnpm format:check         # Check formatting without writing

# Single package
pnpm --filter @llui/dom build
pnpm --filter @llui/dom test
pnpm --filter @llui/dom check

# Single test file (from package dir)
cd packages/dom && pnpm vitest run test/signals/runtime.test.ts

# Benchmarks (js-framework-benchmark)
pnpm bench:setup              # One-time: clone + install + compile the js-framework-benchmark repo,
                              # then build the 5 ticker apps (scripts/setup-bench.ts; idempotent).
                              # Never hand-run the npm ci chain — upstream's root install ERESOLVEs
                              # and a && chain silently skips the installs the harness needs (#81).
pnpm bench                    # Build + run jfb + compare against saved baseline
pnpm bench --runs 3           # N runs, median-of-medians (reduces single-run noise)
pnpm bench --save             # Overwrite baseline with current results
pnpm bench --all              # Also re-run all competitor frameworks (~15 min)
pnpm bench:build              # Build jfb app only (no benchmark run)
```

## Development Approach

- **Test-driven development:** Define the type/shape first, write one or more failing tests, then implement until they pass.
- **Tests live in a separate `test/` folder** within each package (e.g. `packages/core/test/`), not alongside source files.
- **No `any` types** unless strictly unavoidable. `as unknown as X` is a code smell — find a better type or restructure.
- **Nothing is sacred.** There is no legacy code or backward compatibility concern. When changing assumptions, update the docs in `site/content/` (published to [llui.dev](https://llui.dev)) to match.
- **No shortcuts.** Engineering economy, expedience, or "good enough for now" must never drive decisions. The drivers are engineering excellence, sound solutions, correctness, and developer experience. If the correct fix is harder, do the harder thing.

### Mutation testing: an UNFAITHFUL mutation reads as coverage

Mutation testing is this repo's main defence against vacuous tests, and every lint-rule, reconciler and quota change is expected to arrive with a mutation table. In ONE batch (PRs #158–#180) four agents reported a mutation number that was wrong — in every case because the MUTATION was malformed, not because the tests were weak. All four were caught by hand (two by the author, two by review); a green suite catches none of them. The trap is counter-intuitive: **a badly-formed mutation usually reddens MORE tests, not fewer, so it reads as strong coverage.**

- **Verify the mutation reached live code before reading the result** — print or assert the applied diff. PR #158 patched a line whose text appeared TWICE in the file and landed on `replaceUrl` instead, never reaching the code under test; the resulting false "12 green" read as WEAK tests. When a mutation reddens NOTHING, suspect the patch before concluding the test is weak.
- **A mutation must be FAITHFUL: it changes exactly the property under test and leaves every invariant around it intact.** PR #168 dropped the `reserveSlot` guard but left `releaseSlot` unpaired, so `reserved` went NEGATIVE and MASKED the unbounded growth the test existed to expose — green against a genuinely unbounded resurrect, where removing reserve AND release killed it. PR #170's "host stops publishing" written `(() => {})()` put `undefined` into the disposer array, so every test additionally died in teardown with `TypeError: dispose is not a function`: a reported 10/10 red where the faithful mutation gives 7/10. If the mutation also breaks paired bookkeeping, a teardown contract, or throws where the real defect would not, the number measures the breakage, not the property.
- **A mutation cannot redden a test whose assertion the mutation SATISFIES.** A fail-closed mutation cannot kill a test asserting the closed direction, yet two PRs reported "all N red" for suites containing exactly such tests — a number that could not have been measured. Stating per row WHY a survivor survives is what makes a table trustworthy; a partial score (`tag-send-drift`'s 64 of 66, below) is the normal shape of an honest one.
- **Re-run mutations against the FINAL committed code.** One figure in the batch was measured before a TypeScript fix that later widened an assertion, so the number never described the tree that shipped.

## Code Style

- Single quotes, no semicolons, trailing commas
- Prefix unused parameters with `_`
- **Control characters in string literals are written as ESCAPES (`\0`), never as raw bytes.** git has no file-type database — it sniffs, and ONE NUL in the first 8000 bytes makes it call the file binary, after which `git diff`, `git log -p` and GitHub's PR review hide every change to it by default. That is how `packages/markdown/src/keying.ts` (the re-render decision for reused prefix blocks) and `packages/vite-plugin/src/notes/trusted-tasks.ts` (the marker gating an agent spawn) both went unreviewable (#94). Both encodings produce the same string at runtime; only one is diffable. `scripts/test/source-encoding.test.ts` fails the build if a raw NUL comes back
- Configured via `.prettierrc` and `eslint.config.ts` (flat config)

## Architecture Concepts

**Component shape:** `component<State, Msg, Effect>({ name, init, update, view, onEffect? })`. State must be JSON-serializable. Msg and Effect are discriminated unions with a `type` field. `init()` takes NO arguments. `view` receives a `{ state, send }` bag where `state` is a `Signal<State>` — read it with `state.map(s => …)` (derive a reactive value), `state.at('field')` (narrow to a sub-path signal), or `state.peek()` (one-shot read in handlers/effects). Element + structural helpers (`div`, `button`, `text`, `each`, `show`, `branch`, …) are module imports from `@llui/dom`, NOT bag members.

**Composition:**

- **View functions (default):** factor sub-views as plain functions that take signal handles — `header(state.at('header'), send)` or `header(state.map(s => s.header), send)`. They run via the real runtime authoring helpers (which consume handles), so they compose without compilation. Annotate their return as `Renderable` (a list, `readonly Mountable[]`) or `Mountable` (a single element) — NOT `Node`/`Node[]`. Every authoring helper (`el`/`text`/`each`/`show`/…) returns a lazy `Mountable`; the cross-file compiler walker recognizes `Renderable`/`Mountable` (and legacy `Node` shapes) as view-helper returns. A helper called for a side effect (notably `onMount`) is now inert unless its returned `Mountable` is PLACED in the view array — discarding it registers nothing.
- **Library components:** the `connect(state: Signal<Slice>, send, opts?)` + `overlay({ state, send, parts, content })` pattern (see `@llui/components`) returns Signal-handle part bags the consumer spreads onto elements. A full child-component boundary (own update cycle + scope tree) is for independent effect lifecycle / library packaging.

**Reactivity (chunked mask):** there is no path ceiling. Each binding carries a sparse mask of the dependency-path chunks it reads; on update the runtime builds the dirty chunk-set from old→new state (reference-equality per path), gates out non-intersecting bindings, and commits only changed values (output-equality). Structural primitives reconcile and own child scopes. (This replaces the deleted two-word-bitmask / `elSplit` / `__dirty` model.)

**Effects as data:** `update()` returns `[newState, effects]`. The core runtime does NOT special-case any effect type — every effect is passed to the component's `onEffect` handler; with no handler an emitted effect is dropped (the runtime warns in dev). The `@llui/effects` package provides the effect builders (`http`/`cancel`/`debounce`/`sequence`/`race`/`timeout`/`interval`/`delay`/`log`/…) and `handleEffects<E>().else(handler)` (adapt to `onEffect` via `asOnEffect`). `delay(ms, msg)` (alias of `timeout`) and `log(message)` replace the old built-in core `delay`/`log` effects.

**`send()` is synchronous:** in the signal runtime each `send()` runs the reducer and applies the update immediately (no microtask batching). `handle.flush()` is a no-op under the default synchronous scheduler (kept for harness/agent parity); in `raf` mode it force-commits synchronously. **`batch(fn)`** (on the handle AND in the view/`onEffect` bag, alongside `send`) coalesces a burst of `send`s into ONE reconcile: every reducer still runs in order and effects still fire per message, but the DOM commit + subscriber notification are deferred to a single pass against the final state when the outermost `batch` returns. State is applied by the time `batch` returns, so the synchronous contract holds at the boundary — this is the opt-in burst/streaming fast path (drain a websocket frame of N ticks as one re-render; ~2.4× on a 1k-tick burst). The compiler also auto-wraps provably-safe straight-line multi-`send` handlers (a block of only `send(...)` calls) in `batch(...)` and injects `batch` into the bag. There is NO microtask/rAF auto-batching by default (it would break sync predictability). The OPT-IN frame-scheduled mode shipped: `mountApp(container, def, { scheduler: 'raf' })` keeps reducers/effects synchronous (the data contract holds) but coalesces the DOM commit + subscriber notification to one reconcile per animation frame (microtask fallback off-browser; `handle.flush()` forces a synchronous commit) — measured at vanilla parity on the 1k-burst ticker op (5.9ms vs 14.1 per-send).

## Invariants & landmines

Load-bearing rules a change must not violate, and traps a fresh contributor (human or LLM) reliably falls into. When touching the relevant subsystem, treat these as hard constraints — several are unenforced by types/CI and caused real bugs.

**Runtime invariants (`@llui/dom`):**

- **Build-once.** `view()` runs exactly once and builds a static graph of reactive bindings — there is no re-render. Reactivity is the chunked-mask reconciler. A value read outside a binding (e.g. `state.peek()` in a slot) is frozen forever.
- **State is JSON-serializable.** No `Map`/`Set`/`Date`/class instances/functions in State. Violations silently break devtools time-travel, `@llui/test` replay, agent state snapshots, and Vike SSR. Unenforced today — a compiler rule + dev-mode assert is the right fix (a review responsibility until then).
- **`update()` is pure and returns a NEW state object.** The reconciler detects change by reference-equality per path; an in-place mutation is invisible (or makes everything look dirty).
- **A commit happens ONLY inside a commit scope.** A commit can re-enter `send` (a `blur` fired when the commit removes a focused node); a reentrant send must ENQUEUE, or it starts a NESTED drain mid-reconcile and corrupts the scope tree / `removeBetween` into a `NotFoundError`. The reentrancy guard, the queue, the batch depth and the frame scheduling are private to `packages/dom/src/signals/commit-scope.ts` and reachable only through a `CommitToken`, which only `scheduler.withCommitScope(mode, body)` hands out and whose `finally` restores the PRIOR guard state (never a blind `= false`: a nested scope — a `flush()` from an `onEffect` under an active drain — must leave the outer drain believing it is still draining). A new reason to commit adds itself as a `withCommitScope` call; it cannot reach `drain` any other way, and a token that outlived its scope throws. `component.ts` supplies the other half as a `CommitHost` — its `commit()` reports whether the mount was LIVE, and the scheduler clears the pending flag only for a commit that landed, so an `onMount` send stays owed for the post-mount replay. The drain still bails once `isDisposed()` (redundantly with `dispose()`'s queue clear — either alone holds the behaviour). **Read that file's header before changing it**: the three `ScopeMode`s, the effect-frame stack and the one deliberate raf difference are all schedule contract, spelled out there.
- **The commit scheduler's SCHEDULE is contract, and the refactor that moved it did not change it.** What subscribers see and when each message's effects fire are agent/devtools-visible, so `'immediate'` (devtools poke, post-mount replay) and `'frame'` (`onFrame`, `handle.flush()`) commit what is OWED on scope entry and settle after — collapsing that into a plain settle erases a state frame. Each settle round opens its own EFFECT FRAME, saved and restored like the guard flags, so a settle nested in a commit can neither dispatch nor discard the effects the outer round collected (state advances, DOM updates, `onEffect` never fires — the #57 class; a rejected prototype for this refactor shipped exactly that past a green suite). A round that THROWS drops its collected effects — `drain` dispatches from inside its `try`, never its `finally` — because firing them would run `onEffect` against a half-reconciled DOM and strand a `send` made from one. `test/signals/issue-59-reentrant-effect-buffer.test.ts` and `test/signals/scheduler-throw-path.test.ts` pin those three traces and are the only tests in the package that catch them.
- **Keyed `each`/`virtualEach` rows must be one or more STABLE elements** — never a bare fragment or a top-level structural primitive (`show`/`branch`/`each`) as the row root, or reorder has no stable handle (removeChild NotFoundError, duplicated rows). Rows are reused on reorder, so key by stable value and read `index` reactively.
- **Disposing a container-target mount must remove the nodes it inserted** (structural primitives materialize a `DocumentFragment` that empties on insertion — snapshot the attached nodes). **`provide()` context must be snapshotted at each structural primitive's placement** so lazily-built arms/rows still see it.
- **Output-equality is a VALUE-binding optimization; structural specs are exempt.** A structural spec (`show`/`branch`/`each`/`virtualEach`) has an identity `produce` — its `commit` reconciles and needs the whole state to mount an arm/row against — so `Object.is(produced, last)` compares the STATE BUFFER's identity, not the binding's output. `each` recycles two ctx buffers per row and rotates them on every row update while `last` advances only on commit, so one gated-out row update desynchronises them and silently suppresses every later reconcile (issue #52 — a `branch` in a row that stops swapping arms). `SignalBinding.structural` must keep bypassing the check; structural specs de-duplicate inside their own reconcile instead. That makes a redundant structural commit routine, so **every structural reconcile must be side-effect-free when nothing changed** — notably `ArmController.switchTo` short-circuits on the last RECONCILED key, not the mounted arm's key (a key that mounts no arm — a falsy `show` with no `orElse` — leaves `mounted` null, and falling through would hard-detach an arm still animating out).
- **Gatable vs ungatable lists:** a row reading component state via `state.at('x')` is gatable (a state change not touching `x` skips the row); via `state.map(...)` or whole-`state` it is ungatable (every change sweeps every row). This is an O(1)-vs-O(n) perf cliff.

**Compiler invariants (`@llui/compiler`):**

- **The dep analyzer may over-approximate but must NEVER miss a path.** A missed dependency → a mask that gates out a binding it actually reads → permanently stale UI. (Evaluate destructuring/param defaults, object-literal getters, etc.)
- **There is exactly ONE dep analyzer, and everything that answers "which paths does this read" routes through it.** `signals/analyze-deps.ts` (per accessor body) + `signals/extract-deps.ts` (per signal expression, rebasing onto absolute paths) are the analysis; `signals/collect-signal-deps.ts` (per file, for `llui_static_collect_paths`) and `build-manifest.ts` (per exported helper, for the dormant `__llui_deps.json` producer) are DRIVERS over it, not re-implementations. A second one existed — `collect-deps.ts` + `accessor-resolver.ts` + `track-utils.ts`, deleted in #92 — and it diverged in both directions: it truncated every path at two segments, and it only recognized the pre-signal authoring surface (`text(s => s.x)`, `div({title: s => s.x})`, `scope`/`memo`/`track`, none of which `@llui/dom` still exports), so on every real component it reported ZERO paths while the tool presented that as the answer. Truncation is coverage-SOUND (a dep on a prefix covers its descendants, because an immutable update replaces the prefix reference), which is why it never showed up as stale UI and could sit there for a year. A new question about dependencies gets a new driver, never a new walker. `packages/compiler/test/collect-signal-deps.test.ts` pins the depth AND asserts parity with the `deps` arrays the transform actually emits.
- **A driver that walks owes the two disciplines every walker here owes, and the #92 replacement shipped without both.** (1) **An identifier is a root only where it is READ.** `forEachChild` yields identifiers in NAME position — an object-literal key (`connect({ state: state.at('x') })`), a binding `propertyName` (`({ el, state: sig }) => …`), a member name (`opts.state`), a parameter name — and root-matching those reported a whole-state read that never happened, putting a false `opaque: true` on the canonical `connect`/`overlay` wiring. The one name-position identifier that IS a read is a `ShorthandPropertyAssignment` in an object literal. (2) **Rooting is SCOPE-AWARE.** `each(state.at('rows'), key, (state) => …)` hands the arm a plain ROW handle reusing the name; carrying the root in invents top-level paths that do not exist in State. Prune roots with `scopeIntroduces` (exported from `signals/helper-bindings.ts`) — it is the repo's most complete shadowing predicate (params, block `const`/`let`/`var`, hoisted `function`/`class`, `for` initializers, `catch`) and re-deriving shadowing per walker is how the cases at the end of that list get forgotten. Both defects produce a CONFIDENT WRONG ANSWER to an agent, which is the very thing #92 exists to remove, so both are pinned by name in that test file.
- **Parse per real filename ScriptKind** (`.ts`/`.mts`/`.cts` = TS, `.tsx` = TSX) — parsing `.ts` as TSX misparses generic arrows and both skips compilation AND emits bogus lint errors. **There is exactly ONE `ts.createSourceFile` call in the package** (`src/parse.ts`, pinned by `test/parse-module.test.ts`), and every entry point — lint, the transform, the four schema/annotation extractors, the cross-file resolver, `collectSignalDeps`, and `@llui/compiler-ssr`'s `'use client'` transform — takes a `ParsedModule` (lazy, memoized text+tree) instead of a `source: string`. Each of them used to parse the text itself, so ONE dev transform (`devMode || agent`, i.e. every keystroke-save) parsed the same module **17 times** and each sibling type file 8 times (#93). Two consequences to keep: (1) the plugin builds ONE `createModuleCache()` per `transform` and threads it into `ResolveContext.modules`, so reuse does not depend on any caller remembering — the ONLY legitimate second parse of a module is the lint autofix rewriting `code` mid-transform; (2) nothing may MUTATE the shared tree or hang state off a node (a pass that needs per-node state owns a `Map`). The extractors' old hard-coded `'input.ts'`/`'msg.ts'` filenames also meant every `.tsx` component's schemas came out of a TS parse of TSX. Error recovery masked that for most JSX (seven forms tried — self-closing, fragments, conditional, attribute arrows, generic, `/`-in-text — all kept their type aliases), but NOT where recovery swallows the following statement: a `.tsx` with `const list = <ul>{xs.map(x => <li key={x}>{x}</li>)}</ul>` above `export type State` extracted `null`, so an `agent: true` build shipped no `$ss` and nothing errored. With one tree threaded everywhere a wrong ScriptKind is now wrong everywhere at once, which is why `fileName` has no default anywhere and the Vite plugin parses under the query-stripped id (`Widget.tsx?v=abc` otherwise reads as TS — latent, no misparse demonstrated from it, closed anyway).
- **Schema metadata is computed per `component()` call**, not once per file.
- **The injected runtime import must dodge EVERY use of a helper name anywhere in the file, and the dodge must be decided BEFORE lowering.** `transform-component.ts` prepends `import { … } from '@llui/dom'` for the helpers it emitted; that declares top-level bindings, so a file with its own `const el = …` / `function el() {}` / `import { el } from './x'` got a duplicate declaration — a SyntaxError in code that compiled before (#90; the old check only looked at the file's other `@llui/dom` specifiers). `runtime-helpers.ts` plans an ALIAS per collision (`import { el as el$llui }`), threaded into the view transform (`setHelperEmitNames`) so every emitted call site carries it — an edit's text ALSO contains verbatim user code, where a bare `el(...)` legitimately means the user's binding, so a post-hoc rename of emitted text cannot work. Skipping the injection is NOT an alternative: it leaves the lowered call bound to the user's value, which compiles and silently misbehaves. **The collision test is deliberately the coarsest one — does the identifier occur ANYWHERE in the file (`allIdentifierNames`) — and narrowing it to top-level bindings is a REGRESSION, not a cleanup.** Two cases a top-level scan misses, both real: a `var` hoisted out of a block (`if (x) { var el = 1 }`) reaches module scope and re-declares the import; and a binding that merely SHADOWS it at the emitted call site (`view: () => { const el = …; return […] }` — block-body views ARE lowered) rebinds the lowered call to the user's value with no error anywhere. Over-approximating (a `type el = …`, a property name) only costs an alias nobody needed; under-approximating costs a SyntaxError or a silently wrong call. The one carve-out is the subtraction: a `@llui/dom` import binding the helper under its OWN name IS the helper, so it is emitted bare and not re-imported — but `import { text as el }` binds `el` to a different export and therefore collides.
- **Every agent annotation argument goes through ONE tokenizer** (`packages/compiler/src/annotation-args.ts`), never a per-tag regex. A `["“]([^"”]*)["”]` character class cannot express a quoted string — it stops at the first quote, escaped or not — so `@routeGated`/`@validates`/`@intent`/`@example`/`@warning`/`@emits`/`@should` each truncated a predicate carrying a quote, and the escape-your-quotes workaround the docs advertised produced a predicate ending in a backslash (#89). The damage is INVISIBLE: `@llui/agent` compiles these strings with `new Function` inside a try/catch, so a truncated `@routeGated` degrades to an ALWAYS-OPEN gate and a truncated `@validates` to ACCEPT EVERYTHING — no crash, on a security-adjacent annotation. Keep that try/catch (defence in depth) but never treat it as the guard. The grammar DROPS what it cannot read unambiguously and `agent-annotation-syntax` fails the build on the same input — TWO checks: the argument grammar, plus (for `@routeGated`/`@validates` only) that the captured predicate PARSES as JS, since `@validates("")` or an unbalanced paren is well-quoted and still degrades to accept-all. The rule is scoped to the JSDoc positions the extractors actually read (type alias, its union members, property signatures) because framework sources document the grammar in prose (`@emits("k1", "k2", ...)`) and flagging that would fail valid builds. `@llui/vite-plugin` runs it on NON-component modules AND — critically — on every sibling the cross-file resolver reads (`readSource`), because the canonical `import type { Msg } from './msg'` is erased by esbuild: `msg.ts` never enters the module graph, is never transformed, yet its annotations still ship as `$ma`. Report against the SIBLING's path, and COLLECT rather than throw from `readSource` (`findTypeSource` wraps it in best-effort try/catch that would swallow a `this.error`).
- **A `tagSend` variant list and the `type` its handler dispatches are ONE fact stated twice, and both halves are now checked.** `libraryVariants` becomes `__lluiVariants`, read at `packages/dom/src/signals/element.ts` and surfaced to the agent as "which Msg variants can this control emit" — so a drifted tag is a string that LIES to a model, with no runtime symptom (#118, the class of #89 and #92). The compiler-emitted tags are derived from the `send` call and cannot drift; every HAND-WRITTEN call site can. TWO guards, neither sufficient alone: the TYPE (`libraryVariants: readonly M['type'][]` — `tagSend` no longer takes `send: unknown`) rejects a name that is not a Msg variant at all, including where the handler is a named function no analysis can read (`tagSend(send, ['hide'], dismissOnEscape)`); and the `tag-send-drift` lint rule READS the handler and rejects a tag naming the WRONG variant, which type-checks fine since `'touch'` and `'blur'` are equally valid `M['type']`. The rule's two directions have DIFFERENT preconditions and the asymmetry is the design. DISPATCHED-BUT-UNDECLARED is reported whenever the dispatch is ATTRIBUTABLE — the `send` being called must still RESOLVE to the tagged dispatcher, and the code containing it must RUN when the handler runs. Neither is paperwork: `items.forEach(({ send }) => send({type:'inner'}))` and `const send = other` rebind the name to a different function, and a merely RETURNED closure never runs, so all three reported a variant the control cannot emit until the walk was pruned with `scopeIntroduces` (the repo's one shadowing predicate — never re-derive shadowing per walker) and taught to skip returned functions and nested `tagSend` handlers. RETURNED has TWO halves, and the position is not covered until BOTH are: what a returned value can sit INSIDE, and what can sit THERE. (1) The CONTAINERS are every position whose value can BECOME the returned value with NO CALL in between, not just the direct return operand — a returned object or array literal (`return { h: () => send({type:'inner'}) }`, `return [() => …]`), an erased `as`/`satisfies`/parenthesis/`!`, a conditional ARM, a `??`/`||`/`&&`/comma operand, a returned CLASS EXPRESSION's members, a class field's initializer — and attributing a closure in any of them was a direction-1 false positive on code that type-checks (#157). (2) The DEFERRED-BODY kinds are every node whose body does not run when the literal holding it is built: an arrow, a function EXPRESSION, a METHOD SHORTHAND, a getter, a setter, a constructor. #157 widened (1) and left (2) reading arrow-or-function-expression only, so `return { h() { send({type:'inner'}) } }` stayed flagged while the identical `return { h: function () { … } }` did not — the verdict decided purely by the SPELLING, and falling on the MORE idiomatic one (#182: the same defect one node KIND out instead of one position in, found by review of the #157 fix, on prose that had already claimed 'the whole of the position'). The boundary is still the call: `return items.map(() => send({type:'x'}))` and `use({ h: () => send({type:'x'}) })` DO run, and treating a call argument as just another container would switch direction 1 off for the most common dispatch shape there is (`setTimeout`/`map`/`forEach`). Several things inside a returned class run too, which is why a class expression is a transparent CONTAINER and NEVER a skipped subtree: a `static { … }` block and a `static h = …` initializer evaluate WHEN THE CLASS EXPRESSION DOES, i.e. inside the handler, and a heritage clause (`extends mix(…)`) is not a member. TREAT THAT AS A CHECKED LIST, NOT A CLOSED ONE — every widening of this function so far has been "the same thing one position/kind further out" (#157 → #182 → #194), and the honest statement is that these are the positions that have been ENUMERATED AND TESTED, not a proof that no fourth exists. The same exception recurs one level down, ON THE MEMBER NODE ITSELF, which IS skipped whole: a COMPUTED member name (`{ [k()]() {} }` evaluates `k()` when the literal is built) and every DECORATOR — the member's own and its PARAMETERS' — are evaluated at build time and are rescued by name in `memberBuildTimeExpressions` (a parameter DEFAULT is deliberately not: it runs when the member is CALLED, the deferred half). Decorators were the miss #194 caught, and its shape is the tell: rescuing one position by name silently answers "no" for every sibling position on the same node, so the next member-level position added to TypeScript is missed by DEFAULT. Rescued positions take the OUTER liveness, never the member's `inScope` — a computed key and a decorator are both evaluated outside the member's own parameter scope, so `{ [send({type:'KEY'})](send: unknown) {} }` must not be pruned by that parameter (the class expression's self-name still prunes, because it is bound one scope further out and is already in `live`). Membership is TESTED (`parent.properties.some(p => p === cur)`, never a bare `true`): an unconditional yes answers for positions it never looked at, and is precisely the shape that turns unsound the day a kind is added above it. THE SCAN MUST START AT THE HANDLER NODE, NOT ITS BODY: the nearest rebinding scope is the handler's OWN parameter list, so a walk beginning at `handler.body` prunes every shadow except the one closest to the tag — `({ send }: Ctx) => send({type:'inner'})` and `(send: Ctx['send']) => …` are the `forEach` case exactly one scope up, and both fired on code that type-checks clean. The parameter list is also CODE: a default runs on every call, so a call there costs completeness and a dispatcher mention there escapes (`(e = compute()) => …`, `(_h = register(send)) => …` both claimed a completeness the handler had not earned). Walk EVERY position a default can be written in — `p.initializer` (the default of a whole parameter) AND the defaults nested inside `p.name` when it is a BINDING PATTERN (`({ x = compute() })`, `([x = send({type:'a'})])`, `({ o: { x = compute() } })`), which hang off `BindingElement`s and are reached only by walking the pattern — and pass `!scopeIntroduces(handler, name)` as their liveness, since defaults evaluate in the parameter scope and so take the same liveness as the body. THIS DEFECT HAS NOW SURFACED FOUR TIMES, each one position further in (body-only → parameter list → parameter initializers → pattern defaults); the next walker that says "the parameter list" must mean the whole of it, or it will surface a fifth time. A plain identifier `p.name` is skipped on purpose: it IS the binding, so if it spells the dispatcher then `scopeIntroduces` has already made liveness false, and a name in DECLARATION position is never a read. CLOSED in the same family (#153): `scopeIntroduces` did not know a function/class EXPRESSION's own NAME is a binding scoped over its own subtree — that is how a self-recursive function expression calls itself — so `tagSend(send, ['open'], function send(m?) { send({type:'inner'}) })` false-positived in BOTH directions. The fix is in `helper-bindings.ts` (never per walker), so it is SHARED with `HelperBindings.isShadowed` and therefore with LOWERING and every other signal rule: a `component(` call inside a self-named factory used to be compiled as a framework component, `empty-props` used to fire on `function div() { div({}, []) }`, and `collect-signal-deps` used to invent top-level paths from reads inside a `function state(…)`. The LOWERING row needs its exact wording: a `function div(row) { return [div([])] }` row renderer used to have its self-call RECOGNIZED as the `@llui/dom` helper and lowered into a real `<div>`; it is now left as written — and since **#181** the whole `each` is left verbatim too, so a self-recursive row renderer now compiles CORRECTLY (that row used to carry the opposite warning; both halves are fixed). #181 was the second half and was independent of #153 — it dropped the name identically on `main`, and for a name colliding with no helper (`render: function renderRow(row) { return [div([renderRow(row)])] }` emitted an equally unbound `renderRow`), so `scopeIntroduces` was not involved in either direction. The mechanism: every lowering RELOCATES the callback's body out of the function that named it — an arm becomes `(getCtx) => [...]`, the row factory becomes `(doc, getCtx) => {…}` plus per-each-site hoisted consts, an inlined helper's body is spliced into its caller — and a function EXPRESSION's own name (a binding scoped to its own subtree, which is how it recurses) does not travel with the body. Nothing else in the emitted module bound it, so the surviving call was a FREE identifier that threw `ReferenceError` on the first row render, in a module that parsed cleanly: `assertParses` passed, and so did the `toContain('div([])')` the test asserted. The fix is `namedFunctionExpressionName` in `transform-view.ts`, consulted at the THREE guarded CALL SITES in that file (the count below, "four of the five", counts something else — the decline-test FIXTURES — so keep the two straight) — `lowerArmArray` (so each's render arm, `show`, `branch`, and `lowerHelperEach`'s mid-tier), `lowerRowFactory` (the direct tier, where the name can land in a hoisted const or the `_build` skeleton), and `inlineHelperRender` (`const other = function rowHelper(…) { … rowHelper … }` spliced its own name into the caller — the same defect one pass over). All three DECLINE to lower and leave the primitive verbatim for the authoring path, which keeps the function exactly as written, self-binding intact; the bail reports the shared reason token `named-function-expression:<name>` so the perf diagnostic names the fix once. Two alternatives were rejected, both of the compiles-and-silently-misbehaves kind: emitting the lowered arrow AS a named function expression rebinds the name to the LOWERED arm (a `(getCtx) => LoweredNode[]`, not the author's `(rowSignal) => Renderable`), and re-declaring the original function inside the emitted arm copies verbatim user source into a different lexical position while doing nothing for the factory path, where the name surfaces outside any prelude's reach. The predicate is deliberately COARSE — EVERY named function expression, referenced or not, rather than "did the name survive the lowered text" — because an incomplete survival scan costs a runtime crash while over-approximating costs an optimization on a shape nobody writes except to recurse; narrowing it is the same regression as narrowing the #90 collision test. The ROW PARAM being dropped alongside the name is NOT a second defect: the emitted arm's parameter is the row CTX accessor, not the row, so the render's own param is dropped only once every read of it has been rewritten to a ctx read, and a read that LEAKS into a verbatim position is rebound in the prelude (`const row = rowHandle(getCtx, 'item')`) — pinned in both directions. `test/signals/transform-component.test.ts` adds a module-wide binding oracle (`unboundIdentifiers`, written independently of the compiler's own collectors) — but state what it actually does, because the honest version is narrower than "the emitted module binds every identifier it emits". It is SCOPE-BLIND, so it catches a name whose bindings are ALL destroyed: four of the FIVE decline-test FIXTURES in that describe block — repro 1 `div`, repro 2 `renderRow`, the factory's `f`, pass-2's `nest` (fixtures, NOT the three call sites above: `lowerArmArray` alone is reached by three of them) — where the relocated body was the name's only binding and the emitted module therefore binds it nowhere while still parsing and still containing the call text — precisely what `assertParses` + `toContain` cannot see. It does NOT catch `inlineHelperRender`: the helper's own declaration (`const other = function rowHelper(…)`) SURVIVES, so the free `rowHelper` in the inlined copy still reads as bound and the oracle returns `[]` on the broken output (a real `ts.Program` reports `TS2304` there). The teeth of THAT test are its `not.toContain('signalEachDirect')` assertion — do not drop it on the strength of the oracle, and do not cite the oracle as a general free-identifier gate (it also over-reports: a global outside its allowlist, or an enum member, reads as free). A DECLARATION is deliberately NOT in the predicate: `function f(){}`/`class C{}` bind in the ENCLOSING scope, which the `Block` branch (and, at module scope, `HelperBindings.fromSourceFile`) already own — for `Block`, `SourceFile`, function bodies and arrow blocks, at any nesting depth, verified per consumer. The one container owned by NEITHER is a `ModuleBlock`: `namespace N { function div(){}; div({}, []) }` still fires `empty-props`. Pre-existing and left open — namespaces are effectively absent from this workspace — but the sentence is "the `Block` branch and `fromSourceFile`", not "every enclosing scope". What #153 also lists as a third false positive is not one: `tagSend(send, ['open'], function send() {})` still reports the over-declaration, identically to the anonymous `() => {}` — the report is direction 2 doing its job on a handler that provably dispatches nothing, not the shadowing gap, and it is pinned as a parity test so a later 'fix' cannot silence direction 2 for every empty handler. DECLARED-BUT-NEVER-DISPATCHED is reported ONLY when the dispatch set is provably COMPLETE, because "I did not see it" is not "it does not happen": `tagSend(send, ['commit'], (e) => commitFromEvent(e))` dispatches one call away. Completeness survives exactly one thing besides a readable dispatch — a zero-arg `e.preventDefault()`-family call on a handler parameter, an ALLOWLIST (`isInertParameterMethodCall`), because every other call, tagged template, `new`, returned function or bare mention of the dispatcher can reach it. Forgiving any call ROOTED at a parameter instead rejected ten shapes of valid code (`cb()`, `ctx.commit()`, `opt.onSelect?.()`, `emit({type:'pick'})`, `e['go']()`, …). The allowlist's own cost lands on the OTHER side and is worth stating to library authors: a non-allowlisted event method on a handler parameter (`e.persist()`, `e.composedPath()`) silently switches the over-declaration check off for that call site — a missed lint, never a broken build, but silent either way. A sound generalization needs a `ts.Program`/checker the string-edit transform does not have; nothing syntactic separates `e.persist()` from `ctx.commit()`. **When the two directions disagree about a shape, BAIL** — an unreported drift is a missed lint, a false positive is a build broken for a consumer who did nothing wrong; every knob above is pinned by a mutation-checked test for that reason. Evidence: over the ~220 `tagSend` call sites in this repo's sources the rule reports ZERO, and mutating one declared variant per file makes it fire in 64 of 66. (Two counting methods circulate and both are right about different things: 219 calls the rule's own `resolveCall` RECOGNIZES, against 228 raw `tagSend(` text matches outside tests — quote the figure loosely.) COVERAGE IS NARROWER THAN IT LOOKS: the rule recognizes `tagSend` only when the file imports it from the `@llui/dom` specifier (or declares no binding for the name at all). A barrel re-export or a RELATIVE import is invisible — including the framework's own `packages/dom/test/signals/handle-parity.test.ts`, which contains the very drift the rule exists to reject. Widening that is a `HelperBindings` change affecting every signal rule AND the transform, where the failure direction flips from a missed lint to false positives and wrong lowering everywhere, so it is deliberately left open rather than guessed at — tracked as **#146**, which is where the blast-radius testing belongs. The list itself is read through `as const`/`satisfies` (the same `unwrapCasts` the dep analyzer uses), because the narrowed signature is exactly what pushes authors to write `as const` and bailing on it switched the rule off for the spelling the type asks for; the unwrap does NOT resolve bindings, so a hoisted `VARIANTS` is still unreadable.
- **Framework lint rules are COMPILE-TIME ERRORS in `@llui/compiler`, never ESLint** — LLMs (and humans in a hurry) ignore warnings, so a non-bypassable build error is the only effective channel. Do NOT reintroduce `@llui/eslint-plugin` or recreate rules as ESLint rules.

**Packaging landmines:**

- **`@llui/dom` (and any package owning the render context) MUST be a `peerDependency` (`workspace:^`) + `devDependency`, NEVER a `dependency`.** As a hard dep, `pnpm publish` pins the resolved version; a consumer on a different `@llui/dom` gets two physical installs, each with its own module-scoped `currentContext`, and every `provide()`/primitive from the consumer's view throws `provide() can only be called inside a component's view()` even though it is. This caused a production outage; the fix is the peer-dep pattern, not `pnpm.overrides`.
- **`typescript` is a `peerDependency` (`>=5.0.0 <7.0.0`) + `devDependency` of `@llui/compiler`, `@llui/compiler-ssr` and `@llui/vite-plugin`, NEVER a `dependency`** (issue #64). Same failure shape as the `@llui/dom` rule above: a hard dep pins the published version, so a consumer with its own TypeScript gets a second physical install and the compiler analyses their sources with a DIFFERENT `ts` than they compile with — two `SyntaxKind` tables, one silently wrong dep mask. The floor is 5.0 because the newest API in use is `ts.isSatisfiesExpression` (TS 4.9); the ceiling is a major because TypeScript does not follow semver. All three must carry the SAME range (they install together), and it must stay REQUIRED — `import ts from 'typescript'` runs at module load, so an optional peer trades an install warning for a MODULE_NOT_FOUND while Vite loads the config. `packages/compiler/test/typescript-peer-dependency.test.ts` fails the build if any of this drifts.
- **`tsc` does not clean `dist/`.** Deleted-source artifacts linger and ship unless cleaned before pack (`scripts/publish.sh` now `rm -rf dist` before building). Cross-package `@llui/*` refs are `workspace:*` (pnpm rewrites at pack). `__llui_deps.json` is no longer emitted into tarballs (see Active proposals).
- **The compiler↔runtime metadata ABI must move in lockstep, and its names must be FINAL at emit time.** `@llui/compiler` WRITES the six agent/devtools property keys (`$ms`/`$es`/`$ss`/`$ma`/`$sh`/`$cm`) onto every compiled `component({...})` literal; `@llui/dom` (debug registry) and `@llui/agent` (LAP handshake) READ them. Writer and readers land in DIFFERENT bundle chunks under any vendor split — stock `manualChunks: { vendor: ['@llui/dom'] }` is enough — so nothing may rewrite the name after emission. A post-bundle rename pass scoped to chunks containing compiled modules did exactly that and left the runtime chunk reading the old name: every schema silently `undefined` in production `agent: true` builds, with no error anywhere (issue #45). The table is declared TWICE — `packages/compiler/src/emit-names.ts` and `packages/dom/src/signals/compiler-keys.ts` — because `@llui/dom` must stay dependency-free while the compiler pulls in `typescript`; `packages/dom/test/signals/compiler-metadata-abi.test.ts` fails the build if the two diverge. Change a key in BOTH, and treat any value change as breaking: a consumer on a new compiler with an old runtime reproduces #45 and the runtime CANNOT detect it (an absent key is indistinguishable from a build that emitted no metadata). `@llui/vite-plugin` therefore carries a `@llui/dom` peer range so the package manager catches the skew; `@llui/compiler` cannot declare one — a dev-dep edge back to `@llui/dom` would make the workspace graph cyclic, since `@llui/dom` dev-depends on the compiler for its tests.
- **Do NOT resurrect deleted code.** Off-limits (git history has it if ever needed): the v2c compiler-module registry (`module.ts`/`ModuleRegistry`), the introspection/devtools factories, the `@llui/compiler-{introspection,devtools}` packages, the cross-file walker (`walkProgram`/`cross-file-walker.ts`), the second dep analyzer (`collect-deps.ts` / `accessor-resolver.ts` / `track-utils.ts`, #92), `@llui/eslint-plugin`, and the two-word bitmask / `elSplit` / `__dirty` reactivity model. Docs live in `site/content/` — `docs/designs/` was removed; do not reference it.

**Protocol:** LAP is at **v2** (breaking): frames are zod-validated, `expiresAt` is milliseconds on the wire, and version skew terminates the pairing. Bump the app's shipped `@llui/agent` client and its server together.

**Maintainer workflow skills** (in `.claude/skills/`) encode the exact, easy-to-get-wrong procedures for adding a structural primitive, a compiler lint rule, a headless component, or a package. Consult the matching one before that kind of change. (`llui-app-dev` is the _consumer_-facing skill for app code, not internals.)

## Active proposals

Major architectural changes in flight. Read before touching the relevant packages:

- **v2 Compiler Architecture** (`docs/proposals/v2-compiler/`) — partially realized by the signals migration: `@llui/compiler` is a standalone package (extracted from `@llui/vite-plugin`), and cross-file Msg/State/Effect analysis is live (`cross-file-resolver.ts`, wired into the vite-plugin). The **live** transform path is `transformSignalComponentSource` (a single string-edit signal transform); it emits agent/devtools metadata **inline** (its own `sharedMetaProps`), NOT through a registry.

  **Superseded/removed (do not resurrect without a reason):**
  - The v2c compiler-module registry (`module.ts` `CompilerModule`/`ModuleRegistry`), the introspection/devtools factories (`introspection-factory.ts`), and the `@llui/compiler-{introspection,devtools}` packages were **deleted** — they were only ever driven by the `transformLlui` orchestrator, which the signals migration replaced with `transformSignalComponentSource` (inline metadata emission). The extraction functions live in `@llui/compiler` (`msg-schema.ts`, `state-schema.ts`, `msg-annotations.ts`, `schema-hash.ts`, `binding-descriptors.ts`) and are called inline by the transform.
  - The legacy cross-file dep-analysis **walker** (`walkProgram`/`crossFileAccessorPaths` in `cross-file-walker.ts`) was **deleted** — it was the v2b transform path, removed from the live route when the signal transform became the only compilation route. The live cross-file work uses `cross-file-resolver.ts` (Msg/State/Effect schema resolution) + the signal transform's own dep analyzer (`analyze-deps.ts`/`extract-deps.ts`).

  **Dormant-but-kept:** The cross-package library ABI (`__llui_deps.json`, schema v2). The producer tooling (`build-manifest.ts`, `scripts/emit-deps.mjs`) is kept in-repo but **no longer emitted into published tarballs** — `scripts/publish.sh` stopped shipping it (it was ~191 KB of dead weight across the stack for a consumer that doesn't exist). The **consumer** narrowing is **not wired into the live transform** (it needs a `ts.Program`/checker the string-edit transform lacks; phase 3 was evidence-closed 2026-06-10 — zero qualifying call sites in real consumers). `manifest-resolve.ts` is kept as dormant forward-compat. The producer's per-parameter read analysis is `signals/analyze-deps.ts`, the one live analyzer — it used to be `collect-deps.ts` / `accessor-resolver.ts` / `track-utils.ts`, which #92 **deleted** (see the compiler invariants above); nothing in the repo imports them and they must not come back. If a checker-backed consumer ever lands, re-enable the emit in `publish.sh` (producer + consumer + E2E test together). See the status note in `docs/publishing-a-precompiled-library.md`.

  Note there is no runtime `track()` _primitive_ in `@llui/dom` — only the compiler annotation. The proposal predates the signal runtime, so its references to the legacy runtime (`update-loop.ts`), the deleted `@llui/eslint-plugin`, and the two-word bitmask are historical — read it for the module-system direction, not the runtime model.
