# `@llui/dom` runtime: concepts and invariants

_Detail behind the short rules in the root `CLAUDE.md` (Architecture concepts, Runtime invariants). Moved here verbatim so the always-loaded instructions stay small; read this before changing the area it covers._

## What is LLui (full)

LLui is a compile-time-optimized web framework built on The Elm Architecture (TEA), designed for LLM-first authoring. It runs on a **signal** runtime (`@llui/dom` — a single import surface; there is no legacy runtime and no `/signals` subpath). There is no virtual DOM — `view()` runs once at mount, building real DOM nodes with reactive bindings. State changes drive a **chunked-mask reconciler**: each binding carries a sparse mask of the dependency-path chunks it reads; on update the runtime computes the dirty chunk-set from old→new state (reference-equality per path), gates out bindings whose mask doesn't intersect it, then commits only values that actually changed (output-equality). Structural primitives (`branch`, `each`, `show`, plus `unsafeHtml`/`lazy`/`virtualEach`/`foreign`/`portal`/`provide`) are **lazy `Mountable`s** — recipes that build their live nodes and register their reconcile spec / child scope at the point they are _placed_ (materialized by `populate` for element children and by `runBuild` for a build's returned array, both under a live build context), not at construction. So a `Mountable` captured in a variable and reused inside a toggling `show`/`branch` arm rebuilds fresh on every remount (spec lands in the placing scope); placing one twice yields two independent live instances. They reconcile arms/keyed rows and own child scopes.

The Vite plugin runs a **single signal transform** (`@llui/compiler`) via the TypeScript Compiler API: it lowers signal expressions in a component's DIRECT view to runtime helpers (`signalText`/`el`/`react`/`signalEach`/…) as an optimization, emits introspection metadata, and runs the signal lint rules as non-bypassable build errors. Anything it can't lower (view-helper functions, block-body views) runs via the real runtime authoring helpers (which consume signal handles), so both forms coexist.

## Architecture concepts (full)

**Component shape:** `component<State, Msg, Effect>({ name, init, update, view, onEffect? })`. State must be JSON-serializable. Msg and Effect are discriminated unions with a `type` field. `init()` takes NO arguments. `view` receives a `{ state, send }` bag where `state` is a `Signal<State>` — read it with `state.map(s => …)` (derive a reactive value), `state.at('field')` (narrow to a sub-path signal), or `state.peek()` (one-shot read in handlers/effects). Element + structural helpers (`div`, `button`, `text`, `each`, `show`, `branch`, …) are module imports from `@llui/dom`, NOT bag members.

**Composition:**

- **View functions (default):** factor sub-views as plain functions that take signal handles — `header(state.at('header'), send)` or `header(state.map(s => s.header), send)`. They run via the real runtime authoring helpers (which consume handles), so they compose without compilation. Annotate their return as `Renderable` (a list, `readonly Mountable[]`) or `Mountable` (a single element) — NOT `Node`/`Node[]`. Every authoring helper (`el`/`text`/`each`/`show`/…) returns a lazy `Mountable`; the cross-file compiler walker recognizes `Renderable`/`Mountable` (and legacy `Node` shapes) as view-helper returns. A helper called for a side effect (notably `onMount`) is now inert unless its returned `Mountable` is PLACED in the view array — discarding it registers nothing.
- **Library components:** the `connect(state: Signal<Slice>, send, opts?)` + `overlay({ state, send, parts, content })` pattern (see `@llui/components`) returns Signal-handle part bags the consumer spreads onto elements. WHICH state a `connect` reads is the three-tier choice: T1 static (no state after build) is `connect(constant(v), noSend, opts)`, T2 local (private/transient) is `island({ def })`, T3 hoisted (URL, undo, persistence, a sibling reads it) is `connect(state.at('x'), send)`. `island()` is on the MAIN barrel and is the ordinary answer for private widget state, not an escape hatch — it was `subApp` at `@llui/dom/escape-hatch`, which is now a deprecated alias whose subpath, module header and mandatory `reason` all framed the capability as an anti-pattern and hid it (#231). Measured at N=500 leaves in jsdom: ~2.4x at mount (22.0ms → 53.3ms), ~2x CHEAPER over 50 host updates (2.19ms → 1.14ms), because an island is not a child scope the host reconciler walks — mount cost for update isolation. Props go IN declaratively (`props: state.at('x')` + `onProps: (v) => msg`, a real host-scope binding so it is mask-gated, and the change becomes a MESSAGE rather than a poke at the island's state); messages come OUT through `onHandle`.

**Reactivity (chunked mask):** there is no path ceiling. Each binding carries a sparse mask of the dependency-path chunks it reads; on update the runtime builds the dirty chunk-set from old→new state (reference-equality per path), gates out non-intersecting bindings, and commits only changed values (output-equality). Structural primitives reconcile and own child scopes. (This replaces the deleted two-word-bitmask / `elSplit` / `__dirty` model.)

**Effects as data:** `update()` returns `[newState, effects]`. The core runtime does NOT special-case any effect type — every effect is passed to the component's `onEffect` handler; with no handler an emitted effect is dropped (the runtime warns in dev). The `@llui/effects` package provides the effect builders (`http`/`cancel`/`debounce`/`sequence`/`race`/`timeout`/`interval`/`delay`/`log`/…) and `handleEffects<E>().else(handler)` (adapt to `onEffect` via `asOnEffect`). `delay(ms, msg)` (alias of `timeout`) and `log(message)` replace the old built-in core `delay`/`log` effects.

**`send()` is synchronous:** in the signal runtime each `send()` runs the reducer and applies the update immediately (no microtask batching). `handle.flush()` is a no-op under the default synchronous scheduler (kept for harness/agent parity); in `raf` mode it force-commits synchronously. **`batch(fn)`** (on the handle AND in the view/`onEffect` bag, alongside `send`) coalesces a burst of `send`s into ONE reconcile: every reducer still runs in order and effects still fire per message, but the DOM commit + subscriber notification are deferred to a single pass against the final state when the outermost `batch` returns. State is applied by the time `batch` returns, so the synchronous contract holds at the boundary — this is the opt-in burst/streaming fast path (drain a websocket frame of N ticks as one re-render; ~2.4× on a 1k-tick burst). The compiler also auto-wraps provably-safe straight-line multi-`send` handlers (a block of only `send(...)` calls) in `batch(...)` and injects `batch` into the bag. There is NO microtask/rAF auto-batching by default (it would break sync predictability). The OPT-IN frame-scheduled mode shipped: `mountApp(container, def, { scheduler: 'raf' })` keeps reducers/effects synchronous (the data contract holds) but coalesces the DOM commit + subscriber notification to one reconcile per animation frame (microtask fallback off-browser; `handle.flush()` forces a synchronous commit) — measured at vanilla parity on the 1k-burst ticker op (5.9ms vs 14.1 per-send).

## Runtime invariants

- **Build-once.** `view()` runs exactly once and builds a static graph of reactive bindings — there is no re-render. Reactivity is the chunked-mask reconciler. A value read outside a binding (e.g. `state.peek()` in a slot) is frozen forever.
- **ARIA state attributes are ENUMERATED, not boolean, and `applyAttr` special-cases them.** `aria-checked` / `aria-expanded` / `aria-pressed` / `aria-selected` take the literal strings `"true"` / `"false"`; an empty value is INVALID (assistive tech reports no state) and an absent one is worse still — a `role="switch"` with no `aria-checked` has no state at all. The HTML boolean rule (`true` → `attr=""`, `false` → remove) is correct for `disabled`/`hidden` and wrong for these in BOTH directions, which is what a part bag doing the natural `'aria-checked': state.map((s) => s.checked)` hit: measured across the registry demo, SEVEN part families announced nothing — radio-group item, switch root, toggle root, toggle-group item, rating-group item, tabs trigger, accordion trigger. `applyAttr` now renders a boolean under an `aria-` name as the string; `null`/`undefined` still REMOVE, because that is how a part bag spells "not applicable" (`s.disabled ? 'true' : undefined`) and "false" would assert a state the component never claimed. The carve-out is scoped to the `aria-` prefix on purpose — widening it breaks every native boolean attribute. `test/signals/aria-boolean-attrs.test.ts` pins both directions plus the HTML-boolean non-regression. Found by interacting with a rendered page, not by any check: every class compiled, every test passed, and the DOM was correct-looking.
- **State is JSON-serializable.** No `Map`/`Set`/`Date`/class instances/functions in State. Violations silently break devtools time-travel, `@llui/test` replay, agent state snapshots, and Vike SSR. Unenforced today — a compiler rule + dev-mode assert is the right fix (a review responsibility until then).
- **`update()` is pure and returns a NEW state object.** The reconciler detects change by reference-equality per path; an in-place mutation is invisible (or makes everything look dirty).
- **A commit happens ONLY inside a commit scope.** A commit can re-enter `send` (a `blur` fired when the commit removes a focused node); a reentrant send must ENQUEUE, or it starts a NESTED drain mid-reconcile and corrupts the scope tree / `removeBetween` into a `NotFoundError`. The reentrancy guard, the queue, the batch depth and the frame scheduling are private to `packages/dom/src/signals/commit-scope.ts` and reachable only through a `CommitToken`, which only `scheduler.withCommitScope(mode, body)` hands out and whose `finally` restores the PRIOR guard state (never a blind `= false`: a nested scope — a `flush()` from an `onEffect` under an active drain — must leave the outer drain believing it is still draining). A new reason to commit adds itself as a `withCommitScope` call; it cannot reach `drain` any other way, and a token that outlived its scope throws. `tea-driver.ts` supplies the reducer + nested effect-frame half as a `CommitHost`; both public `createTeaDriver` and `component.ts` use that same core, while the mounted commit callback reports whether the mount was LIVE. The scheduler clears the pending flag only for a commit that landed, so an `onMount` send stays owed for the post-mount replay. Runtime-only controller methods for that replay and a devtools state poke delegate to scheduler entry points that open their own scopes — they are not a second drain door. The drain still bails once `isDisposed()` (redundantly with `dispose()`'s queue clear — either alone holds the behaviour). **Read that file's header before changing it**: the three `ScopeMode`s, the effect-frame stack and the one deliberate raf difference are all schedule contract, spelled out there.
- **The commit scheduler's SCHEDULE is contract, and the refactor that moved it did not change it.** What subscribers see and when each message's effects fire are agent/devtools-visible, so `'immediate'` (devtools poke, post-mount replay) and `'frame'` (`onFrame`, `handle.flush()`) commit what is OWED on scope entry and settle after — collapsing that into a plain settle erases a state frame. Each settle round opens its own EFFECT FRAME, saved and restored like the guard flags, so a settle nested in a commit can neither dispatch nor discard the effects the outer round collected (state advances, DOM updates, `onEffect` never fires — the #57 class; a rejected prototype for this refactor shipped exactly that past a green suite). A round that THROWS drops its collected effects — `drain` dispatches from inside its `try`, never its `finally` — because firing them would run `onEffect` against a half-reconciled DOM and strand a `send` made from one. `test/signals/issue-59-reentrant-effect-buffer.test.ts` and `test/signals/scheduler-throw-path.test.ts` pin those three traces and are the only tests in the package that catch them.
- **Keyed `each`/`virtualEach` rows must be one or more STABLE elements** — never a bare fragment or a top-level structural primitive (`show`/`branch`/`each`) as the row root, or reorder has no stable handle (removeChild NotFoundError, duplicated rows). Rows are reused on reorder, so key by stable value and read `index` reactively. **`island()` and `lazy()` are in that list, and the guard for them is a DIFFERENT one** (#239, CLOSED). They return an ANCHOR COMMENT and mount their real body as its SIBLINGS, so the body is not in the node list the row reconciler moves — but the comment itself is a perfectly stable node, so the `nodeType === 11` fragment check cannot see it. It USED to bite asymmetrically, which is why it was easy to ship: on the SERVER an island's body is a multi-node fragment so `each` threw and the page 500s, while on the CLIENT the row rendered and then corrupted on the first reorder (anchors migrate, mounted bodies stay put) — the worst ordering, since a suite that never reorders stays green on the half that silently corrupts. `src/signals/row-root.ts` is a WeakSet the two primitives mark their anchor in and `each` consults, so both sides now fail alike and at MOUNT — with ONE qualification, since that WeakSet is MODULE-SCOPED: under the two-copies-of-`@llui/dom` packaging landmine the client check fails OPEN (an anchor marked by copy A is invisible to `each` in copy B) and the row corrupts on reorder exactly as it did before. Same failure mode `provide()` already has, identical to pre-change behaviour rather than a regression, and answered by the peer-dependency rule rather than by a second marking mechanism; the fragment half is structural (`nodeType`) and holds regardless. Four things to keep straight: (1) it is NOT a "bare root" rule — the body sits outside the row however many siblings the anchor has, so `[div(…), island({ def })]` is rejected too, and the check is a `some`; (2) `lazy` is the mirror image of `island` — its CLIENT return is a fragment (anchor + fallback + end sentinel), already caught, and its SERVER return is the bare anchor, so marking at anchor CREATION covers both primitives on both sides with one line each; (3) `virtualEach` is deliberately NOT a consumer, and that is the same reason it never needed the fragment check: every row goes into its own absolutely-positioned wrapper element, so the anchor and the body beside it travel together; (4) the diagnostic has TWO BRANCHES and that is the point of it, but the branches are NOT "structural primitives vs isolated instances" — they are FRAGMENT vs ANCHOR, and each isolated instance appears in BOTH, on opposite sides. The fragment branch is `show`/`branch`/`each` PLUS an `island()` on the server and a `lazy()` on the CLIENT; the anchor branch is `island()` on the client and `lazy()` on the server, and it explains the sibling mechanism. Both branches must NAME the isolated-instance primitives that reach them: the old single message said "wrap the conditional body in an element" and sent an author who wrote no conditional hunting for one, and a first cut of this fix left that complaint alive one primitive over — a CLIENT `lazy()` row root read a fragment-branch message naming only `show`/`branch`/`each`, rescued only by the shared tail. Reading item (2) as "`lazy` takes the anchor branch" is the same error: it takes it on the SERVER only. Blast radius before shipping the client throw was MEASURED at zero production call sites across `packages/`, `registry/`, `examples/` and `site/` — the only bare-island row in the tree is the negative fixture in `island-ssr.test.ts`. `row-root.ts` is deliberately not re-exported from `dom.ts`: it is an agreement between the isolated-instance primitives and the one reconciler that rejects them, not a public affordance.
- **The items seam is TOTAL.** `mask.ts:resolveSegs` is undefined-safe by design, so `state.at('items')` over an absent path produces `undefined`; the list reconcile is one step further along that same path and used to be the single link that wasn't (`source.items(state).length`). Both `each` AND `virtualEach` route through `createItemsResolver` (`each.ts`) — nullish renders EMPTY, and dev warns naming the primitive + the dep paths, on each TRANSITION into nullish (never on a legitimately empty array, never repeated while it stays nullish). A total seam trades a loud crash for a silent empty list, which for the reporting page was the worse half, so the warning is not optional decoration — it is the other half of the fix (#165).
- **The mount error boundary is scoped to mounts OUTSIDE a commit round, and it does NOT cover #165's own trigger shape.** `SignalScopeImpl.mount` used to run try/catch-free, so one binding's throw abandoned the enclosing fragment HALF-DRAWN — permanently, since nothing re-mounts it (#165). It is now guarded when `commitRoundDepth === 0`, or when a `setOnBindingError` hook is installed — the hooked case matches main in WHEN it engages but not in what it does, since this loop also re-throws an `LluiFrameworkError` where main's hooked mount path swallowed it (deliberate, and in the fatal direction) — with one try region around the whole loop, resuming at the next binding, reporting through `reportBindingError`: an UNCONDITIONAL `console.error` plus any `setOnBindingError` hook, mirroring `component.ts`'s `reportSubscriberError`, because containment without visibility is exactly what made #165 a confident blank page. `component.ts`'s `commitToDom` opens the round via `withCommitRound` (one try/finally per ROUND — not per scope, not per binding); `commit-scope.ts` is untouched and its private state is not read. Four things a reader gets wrong otherwise:
  1. **READ THIS BEFORE CREDITING THE BOUNDARY WITH #165.** The reported incident's trigger was an AsyncView `branch` swapping a loading arm for a ready arm, and the boundary does NOT cover that shape — the arm mounts from inside the round (guard stands down), and would escape anyway because the parent's `for (const c of this.children) c.update(...)` sweep re-runs the fresh arm IN THE SAME ROUND on the unguarded `update` path. **That page is saved by the items seam above, not by the boundary.** What the boundary covers is the INITIAL mount, where a half-drawn document is permanent.
  2. **In-round behaviour is byte-identical to main, deliberately.** Guarding a mid-`send` mount would contain the throw, complete the round, and DISPATCH effects that `commit-scope.ts` says a round which throws must drop — its stated reason is that they would run `onEffect` against a half-reconciled DOM, and a contained binding failure IS a partially-reconciled DOM. The first cut of #165 shipped that widening as a side effect; it was reverted. Rejected alternatives and the evidence live in **#216**; widen it there, on its own merits, not here.
  3. **Containment buys exactly ONE frame.** A binding contained at mount re-throws unguarded on the first later update that dirties its deps. "The page stays up" is true of that mount, not of the session.
  4. **`update` is untouched, and is still guarded whenever a `setOnBindingError` hook is installed** (agent/devtools) — that is main's behaviour, and it is why "mount is the guarded one" is a default-build statement, not a whole-system one. `test/signals/issue-165-total-items-seam.test.ts` pins four traces (row in-round / row out-of-round / arm in-round / top-level at update); the two named scheduler tests only ever exercise TOP-LEVEL bindings and cannot catch a regression here.
- **A framework authoring error must be an `LluiFrameworkError`, and a test enforces it.** The boundary contains DATA surprises only: an authoring invariant (`framework-error.ts`, detected by BRAND not `instanceof`, exported from the barrel so downstream view-building packages can brand their own) is RE-THROWN, because swallowing "this tree cannot be reconciled" mounts it anyway and resurfaces as a `NotFoundError` several interactions later — the same displacement-from-cause #165 is filed about. Opt-in branding is exactly the hazard: the first cut branded six sites and MISSED `compiledAway()` (the guard behind all six lowering entry points — a mis-wired build silently rendered a blank section) and `derived()`, while the note written beside them claimed `compiledAway` was covered. Nothing failed; review caught it. `test/signals/framework-error-taxonomy.test.ts` now fails the build on any unbranded `throw` in `src/signals/` that is not allow-listed WITH A REASON — do not add a bare `Error` there, and do not silence the test by widening the allowlist without one. The only entry allow-listed today is `debug-collect.ts`'s relay lookup miss (not an authoring invariant); `commit-scope.ts`'s escaped-token invariant is branded because containing scope-tree corruption would be unsafe.
- **`onMount(cb)` hands `cb` the BUILD's root container, NOT the element the call sits inside.** Mounts are collected per BUILD — a component's view, a `branch`/`show` arm, an `each` row — and `runMounts` passes that build's container to every callback in it, so an `onMount` written inside `svg({…}, [ … ])` receives the component's mount container. The JSDoc said "the mounted parent element", which is how this was got wrong twice in one session: an `instanceof SVGElement` guard on the argument failed silently (an icon fetched nothing and drew nothing, with the `<!--onMount-->` marker sitting correctly in the DOM), and a `root.querySelector(...)` written against the wrong subtree still FOUND something — the first match in document order across the whole build, which is #123's shape and is invisible until a second instance of the component exists on the page. Both watcher helpers that take a root (`navigationMenu.watchNavMenuIndicator`, `tabs.watchTabIndicator`) now say so on themselves, because the caller is the only one who can scope it: give the element an id and `root.querySelector('#…')`, or key it with an attribute of your own the way `registry/llui/ui/icons.ts` does. The failure mode is the dangerous half of the pair — the guarded version does NOTHING and the unguarded version does the WRONG thing, and neither throws.
- **An `island()` build inherits its ancestors' CONTEXT and nothing else, and both halves cost something to get right.** The context map is snapshotted at PLACEMENT, the way every other structural primitive does it — it cannot be read from inside the mount callback, because `provide` is immutable-by-swap and has restored the parent map by then, and because the isolated instance builds under a fresh `runBuild` with no parent on the stack. It used to forward only the caller's explicit `contexts`, so an island lost every ancestor-provided value SILENTLY: `@llui/components` routes all i18n through `ComponentLocaleContext`, so every component mounted as an island fell back to default English with no error (#231). An explicit `contexts` map now merges OVER the inherited one; replacing would discard every key it does not name. **`lazy()` is the SAME primitive for this purpose and forwarded no `contexts` AT ALL until #243** — it mounts an isolated instance exactly as `island` does, so it lost every ancestor-provided value the same way, and it added a second silent consequence the locale one cannot show: under a seeded `HEAD_SINK` the loaded component resolved the sink to its `null` DEFAULT and fell back to the live `document.head`, so an `id`-keyed `style({ id: … })` from a lazy child never reached the collector at all — nothing renders wrong, the entry is simply absent. Both primitives now go through ONE helper (`context.ts:mergeContexts`) so the two cannot drift, and `lazy` is where the PLACEMENT-vs-mount distinction is sharpest: its mount is a promise CONTINUATION, so a snapshot taken there is guaranteed to run after `provide` restored the parent map. `lazy`'s ERROR arm deliberately keeps `c.contexts` rather than the merged map — `opts.error(e)` is HOST view code built as an arm in the host's own scope, not the isolated instance, so the caller's `contexts` (extras FOR the loaded component) must not leak into it. Note also which fixture actually measures the distinction: an `each` row / `show` arm with the `provide` OUTSIDE the primitive does NOT — the arm's build ctx is seeded once with the captured map and never swaps it back, so a mount-time read is coincidentally right there. The `provide` has to sit INSIDE the lazily-built arm/row for the swap-and-restore to happen in that ctx; `test/signals/issue-243-lazy-contexts.test.ts` writes both halves into each of its two lazily-built cases. The SSR body is where the "and nothing else" half bites: `runBuild` falls back to the build ON THE STACK when given no `inherit`, and the island's server build runs DURING the host's build — so the obvious spelling (`renderSignalTree`, which passes `inherit: undefined`) silently inherits the host's ctx wholesale, while the CLIENT mount inherits none of it (`mountSignalComponent` runs from `runMounts`, after `ctx` is back to null). A SYNTHETIC parent is what makes the two agree. Measured: an island inside an `each` row inherits `inRow`, `derived` rebases its component-rooted inputs to `ctx.state`, and the server renders `undefined:undefined` against a correct client tree; `headAnon` is the same class one step quieter, and is pinned by its own SSR test (host and island both emit an anonymous `<style>`; inherited, the island's ordinal continues the host's count and hydration duplicates the tag instead of adopting it). **Two FRESH counters agree with each other and are still wrong** — they mint `style:#1` twice and one entry silently overwrites the other (#240) — so what the island is handed is not a fresh counter but a NAMESPACED scope (`build-context.ts:HeadAnonScope`) allocated at PLACEMENT, `~1`/`~2` within the placing instance and nesting as `~1/~2`. Placement is the one point in the sequence both sides reach in the same order, which is why the allocation cannot move into the mount callback: the client mounts an island from `runMounts`, after the host build has finished, so every later position differs between server and client. The seam is public as `mountSignalComponent`'s `headNamespace` / `renderNodes`' fifth argument, because an island is not the only shape that hits this — **`@llui/vike` had the identical defect, measured**: every chain layer is its own build, so a layout's and its page's anonymous `<style>` collapsed to one key, and three layers collapsed to one tag. Each layer now names itself from its INDEX in the chain (`chain.ts:headNamespaceFor`, `L1`, `L2`, …, the outermost keeping the unprefixed namespace so a chain of one matches a plain mount) — never a mount-order counter, which would renumber the surviving layers when a client navigation mounts only a suffix. **`lazy` is the third instance of the same shape and was fixed with it** — it mounts an isolated instance exactly as `island` does, and its allocation must sit ABOVE the `c.ssr` bail, because the server renders nothing for a lazy but the ordinal is POSITIONAL and every later island would otherwise number one lower server-side. The remaining uncovered case is two independent `mountApp` roots in one document, which both take the unprefixed namespace and collide exactly as before; naming one of them is the fix, nothing can do it automatically without breaking hydration parity, and a dev-mode warning in `head.ts` reports the residue (an ANONYMOUS key claimed while another writer holds it — never a named one, whose stacking is the documented feature). The auto-allocated namespaces are marked `~<n>` and caller-supplied ones are VALIDATED (no `/`, no `~`, never empty) so the two spaces are disjoint: `headNamespace: 'i1'` is an ordinary name, which is exactly why the marker is not `i`. Do NOT cite the descriptor registry as a third: `renderNodes` returns only `{ nodes, dispose }`, so nothing server-side reads descriptors and a shared one has no observable — the fresh `Map` is hygiene. `getState` is latent (it would hand `signalLazy`'s error arm the HOST's state). The island DOES render on the server now (build + one mount against `init()`'s seed, effects discarded, no `runMounts`) — but its body reflects `init()`/`initialState`, NOT the first `props` value, because a prop is a binding in the HOST's scope and is only resolvable when that scope reconciles, which is after this build has produced its nodes; inside an `each` row the row ctx it would need does not exist yet, so resolving it early would be wrong exactly where lists are. Hydration needs no claim step: the host's hydrate pass rebuilds and swaps atomically, so the server body is discarded wholesale and both sides start from `init()`.
- **Disposing a container-target mount must remove the nodes it inserted** (structural primitives materialize a `DocumentFragment` that empties on insertion — snapshot the attached nodes). **`provide()` context must be snapshotted at each structural primitive's placement** so lazily-built arms/rows still see it.
- **Output-equality belongs only to `ValueBinding`.** `SignalBinding` is the discriminated union `ValueBinding | StructuralBinding`; only the value variant can enter the output-equality helper. A structural spec (`show`/`branch`/`each`/`virtualEach`) commits whenever its dependency gate passes and still advances its `last` slot so mount-time state is not retained. Structural specs de-duplicate inside their own reconcile, so **every structural reconcile must be side-effect-free when nothing changed** — notably `ArmController.switchTo` short-circuits on the last RECONCILED key, not the mounted arm's key (a key that mounts no arm — a falsy `show` with no `orElse` — leaves `mounted` null, and falling through would hard-detach an arm still animating out).

- **A mapped signal is NOT a `Signal`; `ReadSignal<T>` is the type both kinds share (`types.ts`).** `Signal<T>` is a PATH signal (the view's `state`, anything from `.at()`, an `each` row's `item`/`index`, `constant(v)`) and carries `.at()`; `MappedSignal<T>` (`.map()`/`derived()`) has no path; `ReadSignal<T>` (`map` + `peek`) is their read-only supertype and neither kind is assignable to the other. This used to be false — `MappedSignal extends Signal` with `at: never` — and `never` is assignable to everything, so a helper typed `(job: Signal<Job>) => job.at('status')` type-checked when handed `state.map(...)` and threw at MOUNT. The non-assignability is carried by `MappedSignal.at` being OPTIONAL (an optional property is not assignable to `Signal`'s required method) and typed as a non-callable object whose only key is the fix, so BOTH misuse diagnostics — a `.at()` call, and a mapped argument to a `Signal` parameter — print the remedy in the error text. Do not "simplify" it back to `at: never`: that silently restores the assignability, and `packages/dom/test/signals/signal-types.test.ts`'s `signal hierarchy` block is what goes red. The rule that follows, for every signature in every package: **a parameter/slot/field that only READS a signal is `ReadSignal<T>`; `Signal<T>` only where the code calls `.at()` on it** (plus the view bag's `state` and row handles, which ARE path signals and are handed OUT as such). Outputs built with `.map` (part-bag props) are `ReadSignal<T>` too — typing them `Signal<T>` is now a compile error, not a lie. The runtime handle carrier follows the same split: `ReadHandle<T>` (what `isSignalHandle` narrows to and what every build helper consumes), `SignalHandle<T>` (path), `MappedHandle<T>` (mapped; its throwing `.at` is attached with `Object.defineProperty`, outside the type).
- **A `show` narrowed param is the condition's NON-NULL VIEW; a `branch` narrowed param IS the condition handle** (`authoring.ts`: `render(cond[NON_NULL_VIEW]())`, `armMap[k](value)`), so over a MAPPED condition (`.map`/`derived`) it is a mapped signal and `.at()` on it throws a branded `LluiFrameworkError` naming the path, the `.map((v) => v.<path>)` read and the `ReadSignal<T>` parameter fix. `show` has NO overloads and NO cast: every signal kind declares `[NON_NULL_VIEW]()` returning its own kind over `NonNullable<T>` (`types.ts`, implemented per constructor in `handle.ts`), and `show<View>(cond: ShowCondition<View>, render: (v: View) => …)` infers the arm type from it — a `Signal` condition's arm is a `Signal` (same path, same deps, `.at()` slices exactly as on the condition), a `MappedSignal`'s a `MappedSignal`, a helper's `ReadSignal` parameter's a `ReadSignal`. Overloads could not do this soundly: TypeScript checks overloads against an implementation with its type parameters ERASED to `any`, so an overload lying about the arm's kind or nullability compiles (measured), and the implementation cannot learn which overload was picked. The view CHECKS non-nullness on every read (`non-null-view.ts`): the arm's bindings never see the cleared value, but a handler whose own `send()` closes the arm, or a timer, can read it afterwards — that read throws a branded error telling the author to read the condition instead (`test/signals/show-non-null-view.test.ts`). A slice of the view (`view.at('x')`) is a plain path handle with a non-null GUARD on the view's prefix, never a mapped layer; unguarded path handles keep their single-call `resolveSegments` read. `branch` keeps its overloads and its casts: its arm narrowing depends on the author's discriminant FUNCTION returning the variant's own tag, which no type can connect to `Extract<U, Record<D, K>>`. For `branch`, a `Signal` condition gives the arm a `Signal`; any other `ReadSignal` gives it a `MappedSignal`, so `.at()` is a type error there; the compiler's `at-after-map` reports it in a direct view and `prefer-at-over-map` never recommends it (#267's gallery shell). The throw is no longer reachable from well-typed code (the `MappedSignal` → `Signal` widening it used to escape through is gone); it covers plain JS, `any` and casts, which is why `test/signals/mapped-narrowed-at.test.ts` reaches it through `@ts-expect-error`.
- **Gatable vs ungatable lists:** a row reading component state via `state.at('x')` is gatable (a state change not touching `x` skips the row); via `state.map(...)` or whole-`state` it is ungatable (every change sweeps every row). This is an O(1)-vs-O(n) perf cliff.
- **A STATELESS widget's signal is `constant(v)`, and its dispatcher is `noSend` — neither can be assembled in user land.** All 72 `connect(state, send, opts)` entry points in `@llui/components` demand a signal (`ReadSignal<S>`) + `Send<M>` (71 spelled `export function connect(` plus `async-list`'s generic `export function connect<T>(`, which a non-generic grep misses — it reports 71), so a widget whose values are FIXED FOR THE LIFE OF THE NODE used to force a hoisted state slice per instance. This answers **#235**'s "Note on the state model", NOT #231: #231's motivating widget is a copy button whose `copied` boolean flips and resets after 1.5 s — state that CHANGES — and is answered by `island()`. #231 is the general ladder this sits at the bottom of. Two traps the pair exists to close, both of which produce code that compiles. (1) `pathHandle`'s `produce` resolves its path against **the binding's state**, never against a captured value, so the obvious hack `pathHandle(() => ({ v }), 'v')` renders EMPTY STRING while `peek()` still reports the right value — silent, and pinned by the first test in `packages/dom/test/signals/constant.test.ts`. `constant` is the only handle that IGNORES its state argument. (2) `noSend` is `Send<unknown>`, and `Send<never>` — the intuitive "accepts no messages" spelling — is exactly backwards: `Send<M>` is a function TYPE, so under `strictFunctionTypes` its parameter is contravariant and only `unknown` is assignable to every `Send<M>` (`Send<never>` gives `TS2345: Type 'MeterMsg' is not assignable to type 'never'`). `constant` declares NO deps, so its binding is evaluated once at mount and gated out of every update by the empty mask — the same mechanism `foreign()`'s boot binding relies on — which is also why it needs no row rebasing inside an `each`. Its `.at()` stays SLICEABLE (a constant has a real path structure) while `.map()` keeps the `MappedSignal` no-`.at()` contract. The value is captured BY REFERENCE and the two read paths then DIVERGE if it is mutated: `.at(path)` resolves eagerly and SNAPSHOTS (a view built before `obj.v = 'AFTER'` renders `BEFORE` forever — correct, since the binding ran once), while `peek()` reads through to the LIVE object, so a handler doing `sig.peek().v` sees `AFTER`. Neither is wrong; pass a value you do not intend to mutate. **The compiler now knows about it — see "Signal recognition is by import provenance" in the compiler invariants (#238, CLOSED).**
