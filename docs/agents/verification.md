# Verification discipline

_Detail behind the short rules in the root `CLAUDE.md` (Mutation testing, focus probes, source encoding). Moved here verbatim so the always-loaded instructions stay small; read this before changing the area it covers._

## Mutation testing: an UNFAITHFUL mutation reads as coverage

Mutation testing is this repo's main defence against vacuous tests, and every lint-rule, reconciler and quota change is expected to arrive with a mutation table. In ONE batch (PRs #158–#180) four agents reported a mutation number that was wrong — in every case because the MUTATION was malformed, not because the tests were weak. All four were caught by hand (two by the author, two by review); a green suite catches none of them. The trap is counter-intuitive: **a badly-formed mutation usually reddens MORE tests, not fewer, so it reads as strong coverage.**

- **Verify the mutation reached live code before reading the result** — print or assert the applied diff. PR #158 patched a line whose text appeared TWICE in the file and landed on `replaceUrl` instead, never reaching the code under test; the resulting false "12 green" read as WEAK tests. When a mutation reddens NOTHING, suspect the patch before concluding the test is weak.
- **A mutation must be FAITHFUL: it changes exactly the property under test and leaves every invariant around it intact.** PR #168 dropped the `reserveSlot` guard but left `releaseSlot` unpaired, so `reserved` went NEGATIVE and MASKED the unbounded growth the test existed to expose — green against a genuinely unbounded resurrect, where removing reserve AND release killed it. PR #170's "host stops publishing" written `(() => {})()` put `undefined` into the disposer array, so every test additionally died in teardown with `TypeError: dispose is not a function`: a reported 10/10 red where the faithful mutation gives 7/10. If the mutation also breaks paired bookkeeping, a teardown contract, or throws where the real defect would not, the number measures the breakage, not the property.
- **A mutation cannot redden a test whose assertion the mutation SATISFIES.** A fail-closed mutation cannot kill a test asserting the closed direction, yet two PRs reported "all N red" for suites containing exactly such tests — a number that could not have been measured. Stating per row WHY a survivor survives is what makes a table trustworthy; a partial score (`tag-send-drift`'s 65 of 66, below) is the normal shape of an honest one.
- **A harness that saves-and-restores MULTIPLE patches to the SAME file must restore in REVERSE order, and a forward loop leaves the tree silently mutated.** Each save holds the text _before_ its own patch, so replaying them forward writes `before-patch-2` last — i.e. patch 1 stays applied. Measured in the #257 lane: a two-patch row left `walkDts(dist).slice(1)` in `scripts/check-dist.mjs` after a clean-looking run, and every row that ran afterwards would have been measured against a contaminated tree while reporting normally. It survived only because the row was last and because the tree was checked with `git diff` per file — a file COUNT shows one changed file either way, which is what the next row's own patch would look like. This is the same family as the hardcoded-`ROOT` trap above, one layer in: the `finally` was there and still restored the wrong thing.
- **Re-run mutations against the FINAL committed code.** One figure in the batch was measured before a TypeScript fix that later widened an assertion, so the number never described the tree that shipped.

## Focus/overlay verification: avoid vacuous passes

Focus evidence needs the same discipline as a faithful mutation: first prove the probe can distinguish the broken behavior. Three traps have already produced green results for the wrong reason:

- **Do not use Playwright's `page.focus()` for the action in a focus-restoration probe.** It can re-assert focus after the action and overwrite the restoration being measured. Call the element's raw `HTMLElement.focus()` inside `page.evaluate`, perform the close or teardown there, and observe `document.activeElement` there. `packages/components/test/components/dialog-nested-focus.browser.test.ts` is the executable example.
- **Spread the actual attribute bag, not a wrapper around it.** Part bags may be nested: `MenuItemPartsOf<Scope>` is `{ item: MenuItemAttrs<Scope> & { role: 'menuitem' } }`, so the fixture wiring is `button({ ...parts.item('a').item }, ...)`, not `button({ ...parts.item('a') }, ...)`. The latter silently emits `item="[object Object]"` and omits `role`, `data-part`, and `tabindex="-1"`; assert those expected attributes before interpreting any focus result. `packages/components/test/browser/context-menu-ownership.fixture.ts` exercises the real shape.
- **Make a focus-trap membership assertion cross the boundary it claims to test.** If focus starts on the trap's first focusable, forward Tab can select that same element with or without the disputed container and therefore proves nothing in jsdom. Use the wrap direction that enumerates the disputed edge (for example, Shift+Tab from first to last), or a real-browser scenario whose observed traversal crosses it. `packages/components/test/components/overlay-engine-focus.integration.test.ts` and `context-menu-ownership.browser.test.ts` pin both forms.

## Dimension harnesses mutate through types, never casts

The scenario-renderer dimension harnesses (`navigation-data-*`/`menus-overlays-*`, both paths) mount a scenario's REAL adapter with one field of a declared case input changed and assert the product-published output moved. That mutated input is one no declared case has, so the protocol's typed dispatch cannot produce it — and the harnesses used to bridge the gap with casts (`adapter as (h, input: unknown, …)`, `input as Record<string, unknown>`). A cast checks nothing: tracing every adapter call before and after they were removed showed the registry harness rendering nine inputs OUTSIDE their declared types (Alert `variant: 'outline'`, Badge `'muted'`, Item `'secondary'`, Sidebar `state: 'closed'` ×7), because enum cycles were keyed by field NAME across every scenario, so a "mutation" of one product took another product's values. Those mutations measured the adapter's `else` branch, not the field. Now each family declares one mutator per field per case-input type (`FieldMutators<I>`, `I[F] -> I[F]`, `packages/components/test/styles/scenario-field-mutations.ts`); a harness body is generic per scenario id, so it can only hand an adapter its own input type. A value that is ill-typed ON PURPOSE (protocol validation tests) goes through the `unknown`-taking `decode…` entry points instead. `scripts/test/scenario-harness-casts.test.ts` keeps the harnesses assertion-free (`as const` excepted).

## Control characters in source

**Control characters in string literals are written as ESCAPES (`\0`), never as raw bytes.** git has no file-type database — it sniffs, and ONE NUL in the first 8000 bytes makes it call the file binary, after which `git diff`, `git log -p` and GitHub's PR review hide every change to it by default. That is how `packages/markdown/src/keying.ts` (the re-render decision for reused prefix blocks) and `packages/vite-plugin/src/notes/trusted-tasks.ts` (the marker gating an agent spawn) both went unreviewable (#94). Both encodings produce the same string at runtime; only one is diffable. `scripts/test/source-encoding.test.ts` fails the build if a raw NUL comes back — in **two separate arms, and the second is the one that matters (#260, CLOSED)**. The 8000-byte arm is right for git and was correctly SILENT on the instance that shipped: `scripts/check-readme-examples.mjs` carried a literal U+0000 at offset **26491**, far past the sniff window, so `git diff` worked fine. What broke was every sweep run over that file — **grep classifies by scanning FURTHER than git sniffs, and a NUL anywhere makes it refuse the file and exit 1, which is indistinguishable from "no matches"** (`grep -c` no output vs `grep -ac` 2, measured). During #255 a reviewer's sweep for `\bany\b|as unknown as|@ts-expect-error` over it returned zero hits and was read as CLEAN, and a second check concluded a dependency had been removed entirely; both were caught by hand. A defect that makes an instrument report SUCCESS is worse than one that breaks a build, so the whole-file arm exists to catch it and the two arms are kept separate because their diagnostics differ — one says "git will hide this from review", the other says "your grep just lied to you". Whole-file reading is FREE, measured before it shipped (2202 files / 19.8 MB: 58-80 ms whole-file against 51-106 ms prefix-only, interleaved over three rounds — one `readFileSync` beats open/alloc/read/close per file); the corpus is read ONCE and both verdicts derive from it, lazily rather than at collection time so #193's duration metric can still see the cost. **Its known-bad/known-good self-check is load-bearing, not decoration**: measured, truncating the read back to 8000 bytes with a real NUL planted at 26491 leaves the whole-file ARM green and is killed only by the probe, so both go through ONE detection site — a probe exercising a second copy of the logic certifies itself and nothing else
