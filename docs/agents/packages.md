## `@llui/components`

Dependencies: @llui/dom + @llui/interactions (peers)

Headless components: accordion, dialog, tabs, select, tree-view, timer, tour, etc. Every focus move the overlay machinery makes as its OWN bookkeeping — focus-on-open, the restore to the trigger on teardown, a focus trap activating or releasing — MUST go through `utils/engine-focus.ts` (`engineFocus`/`runEngineFocus`), never a bare `.focus()`. `watchInteractOutside`'s `focusin` path is gated on that depth counter: without it, dismissing a layer focuses its trigger, every SIBLING layer reads that as an outside interaction, and clicking a button INSIDE a popover closes the popover (#155). The guard is deliberately narrow in two directions and both are load-bearing — it gates ONLY the focus path (a genuine pointerdown landing mid-teardown must still dismiss) and it is held for ONE SYNCHRONOUS TURN. State that window precisely: it is the whole synchronous TRANSITIVE CLOSURE of the `.focus()` call — every `focusin` listener it triggers, consumer code and full TEA `send`/reduce/commit cycles included — not just the call itself, and it cannot be narrowed further because `focusin` is dispatched from inside `.focus()`. No USER event can land in it (the event loop is not free), which is the safety-relevant half; the accepted cost is that a consumer's own `focusin` listener moving focus DURING an engine restore has that move swallowed too, leaving a layer open with focus outside it until the next genuine move dismisses it. User-driven moves stay OUT of it even where the engine picks the destination: the focus trap's Tab/Shift+Tab wrap, and the roving/list-navigation focus in `roving.ts`/`table.ts`/`pagination.ts`/`tags-input.ts` — a layer the user Tabs out of must still dismiss. `test/components/overlay-engine-focus.integration.test.ts` covers the three focus-moving sites plus both over-suppression directions. `runEngineFocus` is SYNCHRONOUS BY CONTRACT and the contract is now enforced (#172): an `async` body returns its promise at the first `await`, so the depth counter drops before the focus move ever happens and the call is silently inert — safe (never a stuck guard), which is exactly why nothing surfaced it. The signature rejects a promise-returning body at compile time (`SyncEngineFocusBody`, a conditional collapsing to an uninhabited branded type) and a dev-mode warning catches the thenable a JS/`any` caller can still smuggle past the types; an async-aware variant that holds the guard across an `await` must NOT be added — the guard is safe only because no user event can be delivered inside its window. Two other rules the overlay machinery owes: (1) `nested-layer.ts` is a PER-LAYER registry — a registration names its `owner` (the element it is logically nested inside, normally its trigger) and a lookup names the asking layer's boundary, so "nested inside ME" is answered by DOM containment, transitively through other nested layers. It used to be FLAT, so a modal's `hide`/`focus` sweep exempted every registered layer nested or not, and a modal opened over an open popover left that popover un-`aria-hidden`, un-`inert` and Tab-reachable from inside the modal (#171). Do NOT patch that class by making trap-activate dismiss the layers beneath — the inner dialog's trap pushes BEFORE its own dismissable layer, so it would dismiss the OUTER dialog — nor by re-reading the trap's `focusin` as a user interaction, which IS #155. An UNOWNED registration keeps the flat answer as a documented fallback, and **that fallback is not cosmetic — it leaves #171 UNFIXED for the surface that takes it**: the layer stays exempt from every modal on the page, so a modal opened over it leaves it un-`aria-hidden`, un-`inert` and Tab-reachable from inside the modal, which is #171's headline symptom verbatim. It also AMPLIFIES: an unowned provider's elements join the nesting frontier, so anything owned INSIDE it is dragged into every asking layer too. `context-menu` is the one in-repo case (it is anchorless by design and its `trigger` part is a bare handler bag with no id, so `createOverlay` has nothing to name) and it is measured as still failing in real Chromium — tracked as **#215**, which also records that the obvious fix is NOT owner-only: `anchorId` additionally feeds `dismiss.ignore` and the focus-restore target, so routing an owner through it changes dismissal and focus behaviour as well. Beware the same fallback arriving by accident: `resolveEls` only bails on an unresolvable anchor when `requireAnchor` is set, so an overlay that sets `anchorId` without it (`menubar`) silently degrades to unowned if its trigger id ever fails to resolve. (2) Restoring focus to the anchor is CONDITIONAL on focus having lingered inside the layer — one predicate, `utils/focus-restore.ts:focusLingeredInside`, used by both the engine's teardown and `popover`'s `dismiss.extra`; the popover's copy used to restore unconditionally and yanked focus off the control the user had just moved to (#173) A numeric BOUND in state is a finite number or an ABSENT one — never `±Infinity`, never `NaN` (#177) — and `utils/number.ts:finiteBound` is the ONE normalizer, applied at every WRITE (`init`, and every `setMin`/`setMax`/`setCount`-family reducer). It cannot live in `clamp` where #152 put the VALUE policy: a bound DEFINES the grid rather than naming a position on it, so it never passes through a clamp at all. TWO idioms, chosen by the field's own type. UNBOUNDED-CAPABLE (`number-input`'s `min?`/`max?`, `floating-panel`'s `maxSize`, `meter`'s `from?`/`to?` per band, `breadcrumbs`'s nullable `maxVisible`) stores the absence, OMITTING the key rather than setting it to `undefined` so the JSON round trip is an identity key-for-key — `number-input` used to spell unbounded `min: -Infinity`, so its DEFAULT state rehydrated as `min: null`, a field declared `number` holding `null`. REQUIRED (`angle-slider`, `slider`, `splitter`, `progress`, `pagination`, …) takes the documented default at `init` and DROPS the write in a reducer, because there is no way to spell unbounded in `min: number` and keeping the range the component already had is the only answer that cannot switch clamping off: `NaN` is not nullish, so it survives every `grid.min ?? -Infinity`, and every comparison against it is false — after `setMin: NaN`, `setValue(-9999)` STORED -9999 while the max still clamped. `test/components/bound-serialization.test.ts` sweeps every component that keeps one

## `@llui/cli` (`packages/cli`)

Dependencies: zod

`llui add <item>` — copies registry components (shadcn's distribution model) into a consumer app: resolves `registryDependencies`, rewrites the registry's `@/lib/utils` import to the project's alias or to a RELATIVE path when none is configured (an alias the consumer's tsconfig does not declare resolves nowhere, so relative is the default, not the fallback), and NEVER overwrites an existing file without `--overwrite` — the copied file is the consumer's source and is expected to have been edited. Registry item JSON is a deliberate subset of shadcn's `registry-item.json` and IGNORES unknown keys, so an additive registry change is not breaking. `target`s are validated at LOAD time against `..` and absolute paths, because a registry is remote third-party content and the write site is several calls away.

## `@llui/markdown`

Dependencies: @llui/dom (peer)

Reactive Markdown rendering: `markdown()` parses to mdast and builds live reactive DOM (no HTML string), per-node renderer overrides, streaming-friendly keyed blocks, bundled light/dark themes. The streaming path is incremental on THREE levels, all memoized on NODE IDENTITY (so an mdast tree is IMMUTABLE once parsed — never mutate and re-collect): sealed-leaf prefix reuse (`incremental.ts`), per-block content hashing (`keying.ts`), and document-global definition/footnote collection (`definitions.ts`). The definition table stays WHOLE-DOCUMENT — only the per-block CONTRIBUTIONS are reused — so a definition arriving in the tail still resolves for a reference in the prefix. RESOLVING it is only half the job: whether a reused prefix block actually RE-RENDERS is decided by `keying.ts:referenceFingerprint`, which must cover ALL THREE mdast reference nodes — `linkReference`, `imageReference` AND `footnoteReference` — under `l:`/`f:` namespaces matching `definitions.ts`'s label ids. `footnoteReference` was missing, so `see[^a]` kept its content-hash key and stayed literal text forever once its tail definition arrived, with the tree and the definition table both correct (#84). The DOM is the only place that class of gap is visible, which is why `test/incremental.test.ts` streams generated documents and diffs the live DOM against a cold `mountStatic` at every step

## `@llui/lexical`

Dependencies: @llui/dom + lexical (peer)

Low-level Lexical ↔ signal-runtime binding: `lexicalForeign` seam, plugin contract, DecoratorNode↔LLui sub-view bridge, and the per-editor COMMIT HUB (`createCommitHub` + `ctx.onCommit`/`ctx.withFacts` on `PluginContext`) — one shared `registerUpdateListener` and one editor-state read per commit for every plugin that tracks the selection. A commit is BATCHED (all subscribers refresh, then all buffered emissions drain in subscription order), and the drain splices its batch before delivering it — a re-entrant `withFacts` from a reducer would otherwise re-send everything already delivered. Plugins reach the hub through an ERASED `import type` only, so each stays independently loadable (#75). The seam's `register` and `externalUndo` slots take the SAME shape and differ only in that filling `externalUndo` forces `@lexical/history` off — a symmetry that silently double-applied undo in collab (#72). `EXTERNAL_UNDO_BRAND` (a phantom `unique symbol`) breaks it: `register` is typed `ForeignRegister` (optional `never` at that key), so every PLAIN function still fits but an `ExternalUndoOwner` from `externalUndoOwner()` is a compile error there. Keep `register` branded and `externalUndo` unbranded — reversing either re-opens the hole or breaks `@llui/lexical-loro`'s plain split binding

## `@llui/lexical-collab`

Dependencies: @llui/lexical + @lexical/yjs + yjs (peer)

Opt-in collaborative editing: `yjsCollab` binding over an injected Yjs provider — CRDT sync, scoped undo, presence cursors. The handle exposes NO `register` member (#72): its one registration function is named `externalUndo` — the `lexicalForeign` slot whose mere presence FORCES `@lexical/history` off — and `foreign` bundles it with `seedMode: 'deferred'` as one spreadable fragment. A local undo stack running beside the CRDT one double-applies every undo and diverges the shared document; that used to be a precondition the host had to remember, so do NOT re-add a `register` alias — it re-opens the unsafe wiring. Renaming around it is blocked too: `externalUndo` is an `ExternalUndoOwner` (the `EXTERNAL_UNDO_BRAND` phantom in `@llui/lexical`), which the seam's `register` slot rejects at compile time

## `@llui/lexical-loro`

Dependencies: @llui/lexical + lexical + loro-crdt (peer)

Opt-in collaborative editing over **Loro**: `loroCollab` composes a bidirectional binding into one `register` for `lexicalForeign`. Children are CARRIER maps ordered by a FRACTIONAL INDEX (`pos`), sorted by `(pos, uuid)` — NOT a `LoroMovableList` (ruled out by two 1.13.7 defects pinned in `test/loro-upstream.test.ts`); a same-parent move is ONE `pos` write, so ContainerIDs survive. ## `@llui/components` — charts

- **A chart PROJECTS; it does not branch on its coordinate system.** `scale.ts` maps data into normalized space (`u ∈ [0,1]` along the independent axis, `v ∈ [0,1]` for magnitude) and knows no pixels; `projection.ts` maps normalized space onto the screen and is the ONLY place cartesian and polar differ. `Projection` is one interface (`point`/`line`/`area`/`band`/`gridline`/`tick`/`valueTick`/`locate`) with two implementations, and `chart.ts` never reads `.kind`. That is what makes `coord` one state field: switching it re-projects every mark, gridline, tick, hit test and tooltip anchor from the same series and data — a line becomes a radar outline, a bar a wedge, a rule a ring. Putting the two-way decision inside each mark instead spreads it across line, area, bar, gridline, tick and hit-test code where the six copies drift; see `docs/adr/0003-charts-project-rather-than-branch.md`.
- **`monotone` and `step` are functions of the INDEPENDENT axis, and `horizontal` moves it from x to y.** `path.ts`'s `CurveAxis` names which coordinate plays `t`, and `cartesianProjection` passes `horizontal ? 'y' : 'x'` to `curvePath`/`areaPath`. Running them along x regardless offsets every control point along the wrong axis: measured, a rising four-point series emitted `M150,0C190,25 230,75 270,75`, where the second control already sits at the segment's END instead of two thirds along it, and the next segment then walked backwards. Note what does NOT catch it — the ENDPOINTS are correct in both orientations, so asserting the path advances monotonically passes on the broken output; the property that breaks is where the CONTROLS sit, and the test asserts the exact ⅓/⅔ positions. The `area` half needs the axis threaded too and is easy to miss: a test counting subpaths and checking for a trailing `Z` is green either way, so `test/utils/chart-geometry.test.ts` anchors the area's opening run against `projection.line(...)` instead.
- **`polarProjection` declines `monotone` and `step` and draws `linear`.** Not a gap — monotone cubic's guarantee is that it never overshoots between two samples, and it is defined on `y = f(x)` with increasing `x`. A closed angular loop has no such ordering, so honouring the request draws values nobody measured. `Projection.curves` states the supported set so the limit is introspectable; do not "fix" this by mapping the request onto a cardinal spline.
- **Every path coordinate goes through `path.ts:fmt`.** The reconciler commits on output-equality, so a path recomputed from unchanged data must be BYTE-IDENTICAL or every mark re-commits on every unrelated state change — `0.1 + 0.2` reaches a path as `0.30000000000000004` from one route and `0.3` from another. `fmt` also maps a non-finite coordinate to `0`: one `NaN` voids the WHOLE path element, taking every later command with it.
- **A full circle is TWO arcs, and a full-turn sector is a ring.** A single 360° arc is degenerate — its endpoints coincide and SVG draws nothing, which is the classic vanishing polar gridline.
- **A pie is not a mark type — it is `domain: 'share'`, which moves the magnitude from `v` to `u`.** `ChartState.domain` picks how the INDEPENDENT axis is allocated: `value` gives every category an equal slot (`bandExtent`) and reads magnitude off `v`; `share` allocates each a slot proportional to its value (`shareExtents`) and lets `v` span the whole depth. Polar renders that as a pie/donut, cartesian as one full-width 100%-share bar — the SAME state, so `coord` still re-projects one dataset. A `'pie'` mark was rejected for exactly that reason: it is meaningless under a cartesian projection, so it would have to force polar or draw nothing, which is the invariant ADR 0003 exists to protect. Radial bars needed no new field — `polarProjection` now honours the existing `horizontal` flag, reading "the independent axis moves off its default screen axis" as "off the angle, onto the radius". Three declines go with it, each the same call as polar refusing `monotone`: a share axis has NO padding (the slot is the datum, so a gap makes every slice misstate its share and a full turn stop being 100%); a NEGATIVE value takes no arc (a share of a negative is undefined, and both silent readings either invent data or push the total past 1); and `line`/`area` are DECLINED under a share domain, since an axis whose spacing already encodes the magnitude would put every point at a position meaning something else. Two traps a test will not catch. The pointer hit test must be CONTAINMENT (`nearestShare`), not the nearest-centre `nearestBand` uses — slices tile with no gaps, so a thin wedge beside a wide one loses its own interior to nearest-centre. And the last slice must close at exactly 1 rather than at the accumulated sum: for most inputs the cumulative float sum lands on 1 by luck, so a test with round numbers passes either way — `[310, 779, 45]` is one that genuinely reaches 0.9999999999999999, which on a full turn is a hairline seam of background at 12 o'clock. **`horizontal` under a share domain is a DIFFERENT chart, not a rotation of the same one**: with the slice extents on the independent axis, leaving it off runs them left-to-right across one bar, while turning it on stacks stripes vertically with their HEIGHTS proportional. Both are honest; only the first is what a pie unrolls into, and the geometry probes pass on both — it was caught by looking at the rendered page.
- **Unstacked bar series are laid out SIDE BY SIDE inside each band**, and the slot stays reserved when the legend isolates a series so nothing moves. Overlaying them hides the shorter series AND reads as a stacked chart, so the picture does not merely omit data — it misstates it.
- **Geometry is derived, never stored.** `geometry(state)` is memoized on state identity with `deriveOnce` (as `date-picker` memoizes its day grid). `width`/`height` are user units feeding the `viewBox`, so the whole thing is a pure function of state: no layout read, no `ResizeObserver`, SSR-identical. The bounds `min`/`max` follow #177's UNBOUNDED-CAPABLE idiom — OMIT the key, never `undefined`/`null`/`±Infinity`.
- **Accessibility is a real `<table>`, not the WAI-ARIA graphics roles.** The `<svg>` is `role="img"` named through its own `<title>`/`<desc>` (hence `svgTitle`/`svgDesc` in `@llui/dom`); the numbers live in a visually-hidden `<table>`. `aria-activedescendant` is invalid on `role="img"`, so the keyboard cursor is announced through the tooltip's `role="status"` live region instead. And every drawn layer NAMES A PART (`layer`/`grid`/`axis-label`/`dot`/`mark`) — the first cut did not, so the container's `[data-part='grid']` rules were dead CSS in exactly the way the registry guard exists to catch.

## `@llui/components` — forms

- **Validation is a REDUCER concern and Standard Schema is the seam** (`docs/adr/0002-validation-is-a-reducer-concern.md`). `patterns/form-field` is LLui's react-hook-form: a `validate`/`validateAsync` message runs any Standard Schema, issue PATHS map to flat field names, and `connect` derives every id and every reactive ARIA attribute. The registry's `form` item is shadcn's five recipes re-bound to that part bag — you do not strip RHF, you substitute it. There is deliberately no `FormControl`: upstream's is a Slot forwarding `id`/`aria-describedby`/`aria-invalid` onto its child, and `{...field.control}` already carries exactly those.
- **A part bag must be SPREADABLE.** `formField`'s `errorText` used to carry `message` and `issues` alongside its attributes, making it the one bag in the package a consumer could not spread — spreading it bound a Signal-of-string and a Signal-of-array as DOM attributes, so every call site destructured them back out first. It is now attributes only, plus its own reactive `hidden` (the `date-input` convention); the content moved to a sibling `error: { message, issues, visible }`. Keep the live region MOUNTED and hidden rather than wrapping it in `show(...)`, which unmounts and rebuilds it on every transition.

## `@llui/components` — meter reference ranges (#235)

- **`bands` is the ONE quality model, and the native `<meter>` spelling compiles into it.** `MeterState` carries `bands: MeterBand[]`; `low`/`high`/`optimum` are INIT OPTIONS that `init` turns into three positional segments (`low`/`middle`/`high`) whose TONES follow the HTML gauge rule — the segment holding `optimum` is `optimal`, the one next to it `suboptimal`, the far one `critical`. Nothing reads `state.low` any more, and `MeterThreshold`/`thresholdState` are gone: the vocabulary is `MeterTone = optimal | suboptimal | critical | neutral` and the derivations are `bandAt` / `toneAt`. `neutral` is the ABSENCE of an opinion, deliberately not a synonym for `optimal` — `init()` with no thresholds used to answer `'optimal'`, i.e. a plain disk gauge claiming the reading was good. The one boundary that MOVED: `value === high` now reads as the UPPER segment (it was the middle one), because edges are uniformly half-open.
- **Edges are `[from, to)`, first match in author order, with the top of the track inclusive.** Half-open is what lets adjacent bands tile with no ambiguity, so a lab range whose upper edge is inclusive is written as the NEXT band's `from`. The one exception is `value === to` where `to >= max` — without it a full-scale reading falls in no band at all, which is the one place the uniform rule gives a useless answer, and it is scoped to the TRACK's top rather than to "the last band". A value below every band, above every band, or in a GAP is in NO band, and `data-band` plus `aria-valuetext`'s name are then ABSENT — never the nearest band, because inventing membership misstates a lab result. Nothing is sorted, merged or repaired: overlaps resolve by author order (reversing the list reverses the answer), an INVERTED band matches nothing and lays out at zero width, and duplicate ids both survive with the first winning.
- **Band edges are #177's unbounded-capable idiom one level down** — an unusable edge is OMITTED, so the band reads as open on that side and the JSON round trip stays an identity; normalized at `init` AND at `setBands`. A band with no string `id` is DROPPED: the id is what `parts.band(id)` addresses and what an `each` row keys on.
- **`aria-valuetext` names the band, and only from an explicit `label`.** That is the accessibility win the model exists for — a bare `aria-valuenow` of 47 says nothing about whether the reading is in range. An author-written band defaults its `label` to its `id`; `label: ''` suppresses. The synthesized native segments carry NO label, so `low`/`middle`/`high` are never read out and `aria-valuetext` is byte-unchanged for every pre-band consumer.
- **Geometry is derived, never stored, and the `deriveOnce` cell lives in the `connect()` closure** — not at module scope the way `chart`'s does, because a page of static meters is the motivating case and one shared cell would let two mounted meters evict each other on every update. `parts.bandProps` takes the ROW HANDLE `each` passes and returns SIGNALS, so the bag spreads as is; `chart`'s `markProps` takes a snapshot instead and every call site has to `peek()` the row and re-bind the fields that move.
- **A static meter needs no runtime**: `connect(constant(state), noSend, opts)` resolves the whole part bag, banded track included (`test/stateless-connect.test.ts`). There is deliberately no per-component `geometry()` entry point — #235 asked for one like `chart`'s, and the DECISION is that `constant()` answers it generally rather than adding a 72nd per-component export (#231 is the general ladder). The plain-values half is `peek()`: `constant` is the one handle whose `peek()` reads the captured value rather than a live component state, so `parts.bands.peek()` hands back `MeterBandGeometry[]` outside any view. Write it as two statements — an INLINE `constant(…).peek()` is what `peek-in-slot` reports (#245), while a `const` receiver is silent.
- **The banded `MeterMarker` is clipped by ONE pixel at 0% and 100%, and that is a measured decision.** `-translate-x-1/2` centres a 2px rule on the value, so at the extremes one of its two columns leaves the track and `overflow-hidden` clips it — measured in headless Chromium (1 of 2 painted columns at each end, 2 of 2 in the interior), not reasoned about. The marker stays visible; `overflow-hidden` is what clips the band washes to the rounded track; and the structural alternative splits one recipe into an outer positioned box plus an inner clipping one, which is the `command`-filter-field footgun above. Dropping the translate is strictly worse — the box then sits fully outside the track at 100% and is clipped away entirely.
